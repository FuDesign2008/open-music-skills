# ego-emotion-radar · 七源大众情绪雷达

> **定位**：采集豆瓣/微信读书/知乎/百度/虎扑/B站/微博的热榜与榜单，提炼「情绪母题表」（母题｜需求信号｜一手证据｜选题候选），用于新批次选题调研与「借大众情绪的势」。
> **前置依赖**：`ego-browser` 可用；豆瓣、虎扑需登录态（失效时交创作者扫码，属正常流程）；知乎/百度/微信读书/B站/微博无需登录。

## 何时用 / 不用

**用**：
- 新批次企划前跑选题调研（与 `ego-multi-ai-research` 创作调研同场或前后脚）
- 创作者问「大家最近在关心什么/痛什么」「找点灵感」「借势做什么歌」
- 需要「关系与时刻」选题候选与「当下共鸣度」判断

**不用**：
- 单点事实核查（直接搜索即可，不必全雷达）
- 具体歌曲技法拆解（用 `ego-multi-ai-research` 或个案拆解）
- 已有选题的写词/检查（直接进 `music-creation-workflow` 检查链）

## 核心概念（先读，决定怎么用数据）

1. **情绪母题 ≠ 热点事件**。热点事件 2-3 天死亡；情绪母题（不甘/遗憾/重逢/自愈/被定价/被看见）生命周期周/月级——创作链 1-3 天完全来得及。**只从热点里提炼情绪，不写事件本身**（写听众自己的故事，不写作者的观察）。
2. **借势的作用面是「选题共鸣度」，不是「话题流量」**。站外话题本身不保证带来站内播放；真正收益是歌词/曲名戳中当下情绪。**不得**用本雷达结论去论证「蹭热点能带流量」。
3. **五层雷达**（按层用，不求全）：

```
① 常青命题层（每周一次）：豆瓣话题广场 + 微信读书热搜/飙升/总榜
   → 情绪母题表：大众在痛什么、在找什么答案
② 实时命题层（每 2-3 天）：知乎热榜 + 百度 realtime
   → 捕捉情绪转向/新情绪冒头
③ 叙事细节层（按批）：豆瓣人气创作/小组精选 + 虎扑步行街 + 微博（过滤娱乐）
   → 给歌词提供一手故事、道具、场景、语气
④ 圈层/题材层（按批）：B站热搜 + 百度 novel/movie/teleplay
   → 年轻圈层语言 + 题材趋势判断（不作情绪母题）
⑤ 核查层（按需）：百度/今日头条
```

## 七源评级（实测）

| 源 | 级别 | 形态 | 时效 | 登录 |
|---|---|---|---|---|
| 豆瓣 | **S** | 话题=命题；人气创作=一手叙事；小组日榜=人群画像 | 周/月 | 需登录 |
| 微信读书 | **S** | 书名=大众在找的答案；今日阅读人数=注意力信号 | 周 | 公开 |
| 知乎 | **A+** | 问题句式=实时命题 | 天 | 公开 API |
| 百度 realtime | **A-** | 社会新闻中的强情绪事件 | 小时/天 | 公开 |
| 虎扑 | B+ | 男性视角生活叙事 | 天 | 需登录 |
| B站 | B+ | 年轻圈层梗/社会话题 | 天 | 公开 API |
| 微博 | B | 具体人生时刻，但娱乐八卦占 50%+，必须过滤 | 天 | 公开 API |
| 百度 novel/movie/teleplay | B（趋势） | 题材趋势，**不作情绪母题** | 周 | 公开 |
| 今日头条 | C | 新闻流，**只作事实核查** | 天 | 公开 |

## 采集流程

### 第 1 步：跑采集脚本（七源快照）

```bash
ego-browser nodejs < skills/ego-emotion-radar/scripts/collect.js
```

- 输出：`/tmp/emotion-radar-<YYYY-MM-DD>/emotion-radar-<YYYY-MM-DD>.json`（ego-browser eval 环境无法可靠定位项目根，默认落 /tmp）。
- 脚本逐源采集、单源失败不阻塞其余源；控制台只打印每源抓取字符数（`[ok] key len=N`），完整文本在输出 JSON 里。
- 采集约 2-3 分钟（16 个页面）；**不要**在单源上反复重试（失败即降级）。

### 第 2 步：解析与噪声过滤

| 源 | 保留 | 丢弃 |
|---|---|---|
| 豆瓣话题 | 全部（话题即命题） | — |
| 豆瓣人气创作/小组 | 一手生活叙事 | 纯种草/购物/宠物图 |
| 微信读书 | 热搜榜/飙升榜/总榜/神作潜力 | — |
| 知乎 | 与「关系/人生时刻」相关的问题 | 纯科技/动漫/知识类 |
| 百度 realtime | 民生/情感/职场类新闻 | 时政/国际/体育/财经 |
| 百度 novel/movie/teleplay | 仅记录题材类型分布 | 不提炼母题 |
| 虎扑 | 恋爱区/职场区/校园区生活帖 | NBA/电竞/体育流 |
| B站 | 梗/社会话题（年轻语言参考） | 纯 ACG 剧情讨论 |
| 微博 | 具体人生时刻 | **娱乐八卦（通常占 50%+，必须过滤）** |

### 第 3 步：提炼情绪母题表（核心产出）

**严格使用此模板**（交创作者拍板，不在表内写成稿）：

```markdown
# 情绪母题表（YYYY-MM-DD · N 源快照）

| # | 信号来源（平台+原句/标题） | 情绪母题 | 选题方向（关系/时刻） | 唤醒度 | 时效 |
|---|---|---|---|---|---|
| 1 | 知乎「为什么家长很难接受孩子的平庸？」 | 代际期待/失望与和解 | 父母与孩子·长大一瞬被看见 | 高 | 长 |
| 2 | 豆瓣话题「你受过的委屈，身体一直都记得」 | 委屈/身体记忆 | 被误解的那些年 | 高 | 长 |
| 3 | 微信读书「住小房子的女人」 | 独居/女性安身立命 | 一个人的家 | 中高 | 中 |

**母题聚类**（3-6 组）：<按情绪族归纳>
**避让**：与既有曲库重复的选题（写词前查重）
**建议入选本批**：<2-4 条，注明理由>
```

**提炼判据**（写进每一条之前自问）：
1. 这是「情绪」还是「事件」？事件一律转译为情绪（「老人被中介骗房」→「替父母讨说法的无力」，不是写骗房）。
2. 听众能把自己填进去吗（关系槽位）？
3. 唤醒度够不够（心动/痛/憾/燃/不甘/羞耻/决绝）？低唤醒温柔不算。
4. 有没有可截句的潜力？

### 第 4 步：落盘与接入

- 情绪母题表落项目调研目录（或该批选题依据节）。
- 与 `ego-multi-ai-research` 创作调研结论合并 → 交创作者拍板 → 进入 `music-creation-workflow` 写词。
- **不追溯已发行**；单次结果不直接沉淀为规则（双实例后回议）。

## 采集配方（实测端点）

| 源 | 端点/页面 | 关键点 |
|---|---|---|
| 豆瓣话题 | `https://www.douban.com/gallery/` | 登录态；「换一批看看」可翻页 |
| 豆瓣人气创作 | `https://www.douban.com/explore`、`/group/explore` | 「人气创作」「讨论精选」区块 |
| 微信读书 | `https://weread.qq.com/web/category/{rising,hot_search,newbook,general_novel_rising,all,newrating_publish,newrating_potential_publish}` | 解析「书名/作者/X人今日阅读/推荐值」 |
| 知乎 | `/api/v3/feed/topstory/hot-lists/total?limit=50&desktop=true`（页面内 fetch） | 公开 API，实测返回上限 30 条 |
| 百度 | `https://top.baidu.com/board?tab={homepage,realtime,novel,movie,teleplay}` | 5 tab 分别采集 |
| 虎扑 | `https://bbs.hupu.com/all-gambia`（+ 恋爱区/职场区） | 登录态；滚动加载 |
| B站 | `https://s.search.bilibili.com/main/hotword?limit=50`（页面内 fetch） | 公开 API，50 条 |
| 微博 | `https://m.weibo.cn/api/container/getIndex?containerid=...`（页面内 fetch） | 公开 API，85 条（有效约 60） |

## 陷阱速查表

| # | 症状 | 原因/处理 |
|---|---|---|
| 1 | 豆瓣显示「登录/注册」而非「豆邮 XX」 | 登录态失效 → 交创作者扫码；部分内容未登录也可看，可先降级采集 |
| 2 | 虎扑只有导航与体育流 | 未登录 → 扫码；登录后滚动 3-4 次再解析；定向访问恋爱区/职场区 |
| 3 | 抖音热榜只出页脚 | web 端 SSR/登录态不可达 → **本 skill 不含抖音**；需要时用公开归档（滞后约 1 天） |
| 4 | 知乎 API 只有 30 条 | `limit` 上限 30；要更多需滚动 DOM |
| 5 | 百度 hot-board 直连返回 `parameter err` | 不要直接访问 `hot-event/hot-board`；用 `top.baidu.com/board?tab=...` |
| 6 | 微博热搜娱乐占比过高 | 正常现象（50%+）——按第 2 步过滤，不要因此否定微博全部内容 |
| 7 | 微读页面空白/未渲染 | SPA 需约 6.5-7s 等待；七个榜单逐个 goto，不要连续切换不带等待 |
| 8 | 把热点事件直接当选题写 | 违反「只借情绪不写事件」——必须转译为情绪母题 |

## 与其他 skill 的分工

```
music-trends-report（定方向/市场面）
  → ego-emotion-radar（本 skill：大众情绪面·实时+常青）
  ＋ ego-multi-ai-research 创作调研（深度面：升华方案/受众切口）
  ＋ ego-zhihu-inspiration（真人一手故事面——与豆瓣叙事层互补）
  → 情绪母题表 + 升华方案 → 创作者拍板 → music-creation-workflow 写词
```

**与 ego-zhihu-inspiration 的区别**：后者聚焦知乎高赞真实故事的深度采集（单源深挖）；本 skill 是**七源广度扫描 + 情绪母题提炼**（跨源交叉）。两者可同批并用，不重复。

## 维护

- 平台结构漂移时回写「采集配方」与「陷阱速查表」；新增源先实测可达性再入表。
- 单次快照结论不直接沉淀为创作规则；母题表需创作者拍板后进入写词链。

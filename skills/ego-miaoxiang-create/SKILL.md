# 妙响创作自动化

> 依赖：`ego-browser` + `music.douyin.com` 登录态（studio 创作端与 console 发行端同登录态）。
> 产出：每次生成 2 个候选。平台无账号额度系统（前端零额度 UI、额度类端点全 404），但**模型可被平台整条停用**——可用性以实时探测为准。
> 红线：只用自定义歌词 + 文本风格指令；站内素材（伴奏库/仿写参考/翻唱）会锁字节系权利，丢多平台分发权。

## 核心流程（四步）

```
① 注入 → ② 流程推进（确认卡/音色池/双确认三路） → ③ 生成 → ④ 轮询产出（曲名+时长）
```

## ① 注入消息（配方模板）

**solo 模板**（默认；「人声用 X」是直通确认卡的最快开关）：

```
曲名定为《X》。请为以下歌词谱曲演唱。人声用[男声/女声/男女对唱]。注意：完整演唱全部歌词，不要省略段落，时长 3 到 4 分钟。

风格要求：<自然语言风格指令：流派/乐器/声线特质/BPM/结构要求>

歌词：
<完整歌词含 [Verse]/[Chorus] 等段标>
```

**联合署名模板**（**必须删除「人声用 X」句**；Style 内的声线描述仍会触发快速路径跳池，按「②′ 补救配方」处理）：

```
曲名定为《X》。请为以下歌词谱曲演唱。注意：完整演唱全部歌词，不要省略段落，时长 3 到 4 分钟。

风格要求：<自然语言风格指令：流派/乐器/声线特质/BPM/结构要求>

歌词：
<完整歌词含 [Verse]/[Chorus] 等段标>
```

- **曲名显式传递是资产名对齐的根因级防线**：消息开头「曲名定为《X》」。不显式传递时 Agent 会从歌词意象自取资产名，发行表单预填名随之漂移；已发行后平台禁改，图文导流断链。显式句 + 【歌名】标记双保险（仅标记偶发漏传，显式句为必需）。
- **「人声用 X」显式声明 = round0 直通确认卡的最快开关，但与联合署名互斥**：任何声线描述（显式句或 Style 内的「女声清亮甜」式描述）都会触发快速路径跳池——Agent 把宽泛性别映射为 voice_gender，不调用音色推荐。联合署名场景走「②′ 补救配方」。
- 注入方式：`ta.focus()` + `document.execCommand('insertText', false, txt)`（React contenteditable 受控组件）。

## ② 流程推进（三分支，全部实测）

| 分支 | 特征 | 处理 |
|---|---|---|
| **快速路径** | 出确认卡 + 「生成歌曲」按钮 | 点按钮；若 Agent 仍等文本 → 补发「确认生成」 |
| **音色池路径** | Agent 推荐 2-3 音色（带「选择」按钮） | 点目标音色的「选择」→ 确认卡 → 确认 |
| **双确认路径** | 按钮点击后仍无动作 | 发送文本「确认生成」 |

自适应循环写法：每轮依次探测「生成歌曲按钮 → 选择按钮 → 确认文本」，遇 `generating` break。

## ②′ 音色选择与联合署名

| 路径 | 声线是否生效 | 发行表单是否带出联合艺人 | 结论 |
|---|---|---|---|
| **音色池内点「选择」** | ✅ | ✅ 自动带出（发行表单艺人行双行） | **唯一可靠路径** |
| 音色池关闭后文本回复音色名 | ⚠️ 未验证 | ❌ 表单只有主艺人一行 | 署名失效 |

保证混合署名的操作协议：

1. **必须走音色池点击**——池中无目标音色时，命令 Agent「打开音色选择列表」重新出池，再点「选择」。
2. 文本指定音色仅当曲子本就计划 solo 署名时可用。
3. **发行前核验**：发行表单艺人信息补充区行数 = 预期署名人数；只有一行而预期双人 → 停点，回生成侧查音色是否挂载，不可补救则如实按 solo 发行并记录「署名未生效」。
4. 已发行曲的署名不可回补（表演者修改 = 重新过审，交创作者决定是否值得）。

**快速路径跳池补救配方**：

1. 注入模板**不含**「人声用 X」句（Style 原文照注，含其声线描述——跳池不可避免，接受并转补救）。
2. 确认卡出现后**补发**：「这首歌要用{合作者}的音色演唱，请打开音色选择列表，我要选择{合作者}的音色。」
3. Agent 出音色池（30-45s）→ 池内点目标音色的「选择」。
4. Agent 重出确认卡（人声音色 = 实名）→ **校验确认卡文本含目标声线实名**（不含则不点、重发池请求/坐标+DOM 补点，最多 3 轮）→ 点「生成歌曲」。
5. **权威铁证三处**：确认卡「人声音色 {实名}」、思考流 voice_id/virtual_singer 入参、API Tags 含实名。发行表单艺人行数 = 2 兜底核验。

## ③ 生成与 ④ 轮询

- 生成耗时 ~3-5 分钟/次（批量时平台排队，最长实测 ~1h 才入库资产页）。
- 产出格式：会话流内 `曲名\n时长` 两个候选。
- 轮询防误判：正则用「跨曲名+动作」组合（如 `开始生成《${title}》`），**勿只匹配「开始生成」**——会命中上一首的旧回复。

## 时长攻坚配方

**歌词长度是妙响时长的决定变量**（实测）：

| 歌词规格 | 产出时长 |
|---|---|
| 词牌原词 77 字 | 1:03/0:50（默认短板） |
| 445 字白话词 | 3:00/2:49 |
| 447 字 + 60BPM 慢板 | 2:46/2:46（不足案例） |
| ~490 字 +「3 分半」指令 | 3:15-5:04（区间波动） |
| **612-691 字** | 3:32-4:49（最优产出点约 657 字；>680 字易超 4 分钟头） |
| **530-617 字双批对照** | 530-609 字批主候选 2:20-3:27 普遍偏短；584-617 字 + 慢/中板批双候选达标 3min+；例外：快板/短行词即使词量够也偏短 |

- **配方**：白话词 400-500 字（35-39 行 + 段标）+ 时长指令 + 候选择优。
- ⭐ **时长指令措辞**：用「**时长 3 到 4 分钟**」（单变量实验精准命中），**勿用「拉到 3 分半左右」**（同日对照超发到 4:23-5:07）。
- **时长是概率不是保证**：双候选达标率 ~75%，择优后 100%；批间漂移大（同配方不同时段结果可差 1 分钟以上），候选择优是最后一道保险。
- 候选择优口径：取时长更接近目标区间中值的候选；次候选留作备用。
- **词量天花板**：时长指令强化无法突破词量决定的上限——词 <400 字的曲子产出 2:30-2:45 是常态，改词加长是唯一解（创作决策须创作者拍板）。

## 陷阱速查表（实测踩过）

| 坑 | 处理 |
|---|---|
| **生成前未校验音色** | 池未出现/点选未生效时直接点「生成歌曲」→ 默认声线生成、时长塌到 2:25-2:52（低于 3:00 QC 门）→ 整首作废重生成。**强制门**：点「生成歌曲」前读确认卡文本，必须含目标声线实名（或思考流 voice_id/virtual_singer 实名）；不含 → 不点，重发池请求 + 坐标/DOM 双打，3 轮仍不含 → 弃该次提交并记录 |
| 发送按钮 `sendButtonDisabled`（文本在框内发不出） | 刷新页面重置组件状态 → 重注入 → 立即验按钮 class 不含 Disabled → 点击（长会话/停留久后必现） |
| `execCommand('insertText')` 注入后按钮 disabled | 同上——刷新重置；CDP `Input.insertText` 无效（React 内部状态与 DOM 脱钩） |
| 轮询正则误判 generating（提前 break，静默失败） | 正则限定跨曲名；发送后验证输入框已清空（`boxAfter≈1`）才算发出 |
| 发送按钮 aria-label 是「发送」非 "send" | 选择器写 `css:button[aria-label="发送"], [class*="send"]` |
| Agent 跨会话查询无效 | 「请列出本会话生成歌曲的发行入口」只在对应会话有效——**逐会话索取** |
| 满意度问卷浮层插入 | 在右栏非遮挡，可无视；轮询/点击脚本勿因它中断 |
| 对唱要求传递不稳 | 消息「人声用男女对唱」+ 生成后**必须试听确认**（Agent 可能推理为「未指定人声」） |
| Agent 串行处理多条消息 | 多首消息连发时全部停在音色推荐等选择——逐个补「选择」或补一条「按 XX 搭配继续处理」 |
| **幽灵任务**（Agent 称提交成功但资产页 3h+ 无产出） | ⚠️ 判「无产出」前先按「声线+时间窗」搜卡——候选卡名可能 ≠ 注入名（Agent 重提交时自主起名），按注入名搜卡会**假阴性误判幽灵**。确认真无产出后：回 Agent「重新生成一版新的」→ 双槽位真生成。误发的多余版本无害，留作备选资产。若属平台停用型（脚本逐行同构、9 分钟内从成功变全幽灵），重试无效——先跑模型探针 |
| **平台停用型故障**（流程全绿 + 资产零产出 + 零报错） | 形态：注入→确认卡→生成点击全部正常但资产恒空，**同脚本同流程短时间内从成功变全幽灵 → 变更必在平台侧**。首要排查项 = 模型可用性，非额度/账号：探针 `GET studio_api/aigc/config` 读 `Status`（0=可用/1=禁用）；`model_quota_exceeded` = 模型级话术（manual 模式可换模型规避）。处置：① 常态 10 分钟/轮探测等待恢复（可用窗口历史仅 30-60 分钟，30 分钟周期会整窗错过）② 或切 Status=0 模型（代价=音色变更影响署名，创作者拍板）③ **恢复判据 = 同会话 assets 真产出**（`Status=0` 不充分——解禁后数小时仍可全幽灵） |
| 内容审核拒绝（「内容暂不支持生成/请修改后重试」） | **出现即弃，不必重试**（重试无意义，区别于 3 败累计规则——此形态第 1 次即放弃）。不定位触发词、不代改词（创作决策交创作者） |
| **假启动判据** | 「创作任务已经启动/开始生成/提交成功」等 Agent 文本**一律不算数**；唯一真特征 = 资产页「歌曲 N」标签或资产生成结果 tab |
| **`started=false` /「开始生成」信号缺失** | **不可作放弃判据**：流程推进全绿但工具层信号返回 false ≠ 失败，实测 ~80 秒后 assets API 正常产出双候选。**唯一可靠判据 = assets API 产出**（轮询至超时才可判失败）；信号缺失不提前放弃，不计入失败计数 |
| 拍号文字无响应 | 「6/8 拍」多次注入恒出 4/4——**拍号控制 = 妙响未响应维度**，勿再烧生成额度硬试。检测法：能量包络自相关拍周期分组检验。后续若需摇曳感：换表述单变量实测 / 在唱法编曲层找 / 换生成平台——交创作者拍板 |
| Agent 响应流中途断流 | 形态：思考文本截断 + 页面文本零增长 90s+ + 无加载指示 + 刷新后服务端同态。处置 = 补发「继续」1 轮即恢复；属传输层中断，非生成失败，不计入失败计数 |
| 同曲重复生成：Agent 跨会话感知出确认询问 | 回复「重新生成一版新的（用上条消息全部风格要求）」即破 |
| **产出确认权威 = session/list API** | 页面「歌曲 N」标签渲染滞后（实测 8min+ 未出标签而 API 已有双候选）——轮询超时 ≠ 幽灵任务；幽灵判据 =「API 空 + 页面空」双空。`session/assets` 的 `user_work_info` 是权威确认首选（Status/Title/Duration/VID/WorkID 全字段）；`assets/work?TaskID=` 可能空 data，空时切 `session/assets` |
| **长会话 Agent 上下文滚动 = 旧资产失忆** | 长会话中 Agent 回复「本会话记录里没有找到对应歌曲任务」——会话内索取对旧资产失效。路径：①会话流内滚动找到歌曲卡片 → 界面点选发给 Agent → 再索取 ②session/list API 资产索引定位（推荐）③人工新开会话重述资产重发起 |
| **按台账找库存 = 找不到弹药** | 台账「未发行」记录会系统性过期（登记时点为真、引用时点已假）→ **库存盘点以资产页实查为准**，台账仅作参考 |
| 资产页卡片读不到按钮组 | hover 才渲染按钮组：先 `mouse.move` 到卡片中心再读 innerText；点击姿势 DOM `.click()` 可能不触发、`page.click("text=发行全曲")` 实测成功（两姿势择一可换） |
| **Agent 拒绝给同曲另一版发行入口** | 「发行入口按作品绑定，无法为同名另一版本单独给出链接」——不是故障、是粒度限制，勿反复索取。转**资产页 WorkID 粒度路径**（见「资产页库存盘点」），同名候选按卡片时长辨认 |
| **注入缓存过期：旧稿入库** | 注入物若取自临时缓存快照、而快照早于词稿定稿 → 生成旧稿；音频与平台歌词自洽（都旧版）但与工程稿不符，零报错、靠比对才现形。**纪律**：生成前从工程稿重抽注入物（缓存是优化，不是真相源）+ 以「歌词块 CJK 字数」逐首比对验收；命中后对同缓存批次全量扩散排查 |
| **attach wedge** | 两诱因：(a) 强杀在途 client 会楔死 attach 链——清理须选无在途 invocation 的时刻，逐轮 graceful 退出优于强杀；卡死后 `newPage` 顶替。(b) 锁屏冻结——daemon 正常但 attach 全挂起，或页面陈旧看似正常 + 点击静默无效 + 流程全 true 零产出；页面时钟探针可测。冻结期不空烧（90s 无信号即停跑），解锁自愈；夜间长跑前 `caffeinate` 防休眠 |
| **批量提交 rate_limit** | 短窗内连续提交多席 → 平台限流（Agent 回「提交的任务有点多…稍后重试」，该席零产出）。**退避 ~15 分钟 → 单发重试**（间隔 ≥90s）；失败熔断：连 2 败即停，勿在热窗空烧 |
| **确认卡文案状态假阳性** | 确认卡常见文案「回复『开始生成』我就马上谱曲」——状态机若用 `includes("开始生成")` 判「已提交」会假阳性跳过「生成歌曲」按钮点击 → 全程停在确认卡、资产零产出。判据**短语化**（真提交信号=「Task submitted」；失败=「没能提交成功」）；**兜底 = 始终探测并点击「生成歌曲」按钮**（按钮存在即点，胜过读文案）。同族新形态：状态检查命中了脚本自己发出的消息文本 |
| **注入标题绑定：留白模板偶发漏传** | 注入头仅【歌名】标记时，个别 Agent 不把 title 传进生成 → 资产自取意象名，发行表单预填名漂移。注入头加「曲名定为《X》。」显式句双保险；漏传发生时发行侧手改表单名（表单期是最后窗口，已发行后 console 禁改）——input `readOnly=false`：native setter + 派发 `input`/`change` 事件 → 读回验证 |
| **绿检表观误报** | 签约卡/卡片选中后的绿色边框检测偶报 `NO_GREEN`（样式口径差异），但流程实际已选中并推进。以**流程推进证据**为真判据（能否到「签署协议」步/「生成歌曲」按钮出现） |
| **批量捕获选版·voice 过滤双坑** | ① ego-browser `evaluate` 单参语义：`evaluate(fn, title, voice)` 第二参被丢弃（voice=undefined → 过滤条件静默失效），须数组包参 `evaluate(([t,v]) => …, [title, voice])`；② 跨零点批次卡时间戳跨日（正则容 `1[56]` 勿写死单日）。过滤失效零报错、只选错版 → **过滤器必须带命中数量断言**（预期 2 候选，多出即告警）。「无音色标签」卡 = 性别默认版（角色未生效） |
| **跨 space 表单页定位** | 多 space 并发时同名 label 指向不同页——凭 `page("p7")` 跨 space 定位会改错曲目。**定位一律「URL 含目标 issuedId」精确匹配**；**改表单值前后必读回验证**（读回是误改被抓住的唯一原因） |
| **修正指令落地·全副本同改** | 创作者修正（如声线改配）须一次同步所有副本（生成脚本配置/注入 payload/署名表）——半同步会导致带旧配置启动。**启动前做「修正 vs 配置」交叉核对** |

## 模型可用性探针与停用型故障

**何时用**：Agent 流程全绿但零产出时定位根因；或想判断「现在能不能生成」而不烧一次真实尝试。

- **权威探针**：`GET https://music.douyin.com/studio_api/aigc/config`（无参只读）→ 全量模型表，逐模型读 `Status`：**0=可用 / 1=禁用**（禁用时带 `DisabledSubtitle`）。与 UI 探针同源、更直接（字段级）。
- **`model_quota_exceeded` 的正确解读**：「当前生成额度暂时不可用」= **模型级**后端话术、非账号额度账单——平台 Agent 推理流原文显示：manual 模式会换模型规避，auto 模式禁止自行换模型重试。判读时勿读成「账号额度用光」。
- **无账号额度系统（四路否证）**：前端零额度 UI + 额度/VIP/订单类端点全 404 + 协议零额度条款 + 官方知识库零额度页。第三方「每日免费额度」说法无可指对象，勿据此规划产能。
- **手动换模型通道**：经典创作模式 → 模型选择 → 关闭「自动」开关 → 可选 Status=0 模型。代价 = 音色/persona 变更（影响联合署名前提与已交付专辑音色一致性）——**属创作决策，交创作者拍板，勿自行切换**。
- **故障期处置**：常态 **10 分钟/轮**探测（config 探针零成本；可用窗口短，30 分钟周期会整窗错过）+ **窗口开启即放量**。退避期间可转向库存/存量线工作。
- ⚠️ **`Status` 是时点快照且必要不充分**：解禁后仍可能数小时全幽灵；**恢复判据 = 同会话出 assets 真产出**。别把历史快照当现状，也别按「白天不可用」预设停探（白天窗口实测开过）。
- ⚠️ **窗口形态**：平台可整条停用某模型族（实测 38h+），00:00 左右可能静默恢复；恢复后仍可回落。判断一律以现场探测 + 真产出为准。

## 资产页库存盘点（「生成结果」tab = 库存权威源）

```
① 入口：music.douyin.com/studio/assets → 「生成结果」tab
   （非「对话记录」tab——对话是会话维度；生成结果才是歌曲资产级，含曲名/艺人/时长/生成时间）
② 判发行状态（零成本）：卡片 hover → 按钮组
   「编辑 | 发行全曲」= 未发行（可发行弹药）    「编辑 | 查看详情」= 已发行
③ 发行直通车：hover → 点「发行全曲」→ 开新 tab 正格式直链（issuedId 预绑定音频/歌词/表演者）
   → 直接走发行 skill 的三步向导
```

配套注意：
- 资产页**无发行状态筛选/搜索**（「筛选」仅 AI 生成/编辑器导出维度）→ 滚动定位；但**滚动可达全量**，早期资产也在池内。
- hover 按钮组需**先 mouse.move 到卡片中心**再读 innerText；已发行曲 hover 出「查看详情」而无「发行全曲」——勿据此判定入口失效。
- **发行前仍须 console/songs 交叉验证**（真阴性判据 = 对照组同批已发行曲命中），防「直链预绑定名漂移」。

## 发行衔接（妙响 → 汽水）

- **发行入口 = Agent 会话内链接**：`complete-publish-astra?enter_from=astra&issuedId={生成任务ID}`（一次生成任务 2 候选共享 1 个发行单）。
- **issuedId 时序推断映射法**：会话统一索取多首入口时返回无曲名的 ID 列表 → 按「生成时序 = issuedId 递增」映射曲目 → 发行表单打开时以预绑定标题终核（推断法实测全对，终核兜底防映射错）。
- **双稳入口**：①会话内向 Agent 索取（多曲时要求「逐条注明链接对应的歌曲名」防映射错）②资产页歌曲行内/详情侧边栏「发行全曲」按钮（点击 = 开新 tab 正格式直链）。会话卡「⋯」菜单仅重命名/删除，不是发行入口。
- **WorkID 粒度取入口**：会话入口按作品（WorkID）绑定——Agent 未必给得到你要的那一版。处置 = 走资产页：`studio/assets` →「生成结果」→ 目标版卡片 hover →「发行全曲」→ 开新 tab，即得该版独立 issuedId（同名候选按卡片时长辨认）。用途 = 换版/改判场景：绑定版 QC 不合格时取合格版入口，不必弃单重做整链。**边界**：取入口 ≠ 放行同曲多版；同曲异版发行须创作者显式拍板；弃用版入口不消耗。
- ⚠️ **同名多版本平台放行**：同一工程多版本可各自成单（平台不按曲名查重），但同曲多版本仍受质量门约束——发几版属审美/价值决策，交创作者拍板。
- **适用边界**：「会话内索取」对长会话旧资产失效（上下文已滚动）；旧资产入口走会话流滚动点选 / session/list API 索引 / 人工新开会话。
- complete-publish-astra 表单**无需上传音频**——issuedId 已预绑定音频/歌词/表演者，表单打开即加载。
- **生成侧 QC 下载两通路**：① studio 会话流 `songPlayButton` 触发播放 → fetch hook 抓直链（二次播放起 fetch hook 失效 → CDP `Network.enable` + `requestWillBeSent` 协议级监听兜底）——零发行侧接触，不动 issuedId；② 发行表单打开即自动加载音频（`performance` entries 直接抓取，无需点播放器）。
- 歌词框 ≥80 字下限：工程白话词（400+ 字）天然满足。

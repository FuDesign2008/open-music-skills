# ego-multi-ai-research · 多 AI 站点交叉调研

> **定位**：用 ego-browser 驱动豆包 / Kimi / DeepSeek 等多个外部 AI 站点做「统一问题组」交叉调研——每家多轮深聊 + 第四源平台实况补充，交叉比对产出**共识区 / 分歧区 / 独有洞察区**三分区报告，来源可溯留痕。
> **前置依赖**：`ego-browser` + 至少两家站点登录态（豆包 doubao.com、Kimi kimi.com、DeepSeek chat.deepseek.com）。登录态失效可按降级路径继续，不阻塞。

## 何时用 / 不用

**用**：
- 调研结论要进创作方案（Style/配方/DNA 报告）且题材复杂多维度
- 单源结论拿不准，需要交叉验证
- 创作者对调研深度不满，要升级
- 需要考据级证据（乐谱/一手资料/参数区间）

**不用**：
- 单点快查（平台规则/一个标签含义）——用静态 web 调研即可
- Claude 内部多视角推演——用 multi-agent-debate（无外部检索面差异）

## 两种模式：拆解模式 / 创作调研模式

同一套七步流程，问题组设计分两种模式：

| 模式 | 问的是 | 典型问题组 | 产出落点 |
|---|---|---|---|
| **拆解模式** | 「这首怎么做出来」 | 唱法/旋律/编曲/母带等技法维度 | DNA 报告 / Style 指令 / 配方卡 |
| **创作调研模式** | 「这个选题值不值得做、怎么做才有高级感」 | 意象升华空间/受众共鸣点/高级表达方案/情感哲理渗透 | 选题依据节 + 升华方案候选 + 钻石位候选 |

### 创作调研模式（新选题前置调研）

**何时用（硬门）**：凡新选题创作（新专辑企划/新题材方向/新曲名体系）——写词、定曲名、Style 设计之前，先按本模式调研再创作。**为什么**：单模型对「这个选题能不能写出高级感」的先验容易封闭；多家外部 AI 的检索面/受众面/推理面差异，能在动笔前把选题的升华空间与共鸣切口摊开。

**统一问题组（四维起底下限，可按选题加维至 5-9，维度可增不可砍）**：

1. **意象升华空间**：这个选题的情绪内核是什么？可升到哪些高级/浪漫/想象力意象域（宇宙/星空/魔法/自然/时节/远方/梦境/时间……）？给 3-5 条具体的「意象载体 ↔ 情感内核」配对方案，各自适用什么场景。
2. **受众共鸣点**：谁在听这个主题？什么场景/什么情绪最容易共鸣（代入感/仪式感/陪伴感）？给出可感知的受众画像与共鸣切口。
3. **高级表达方案**：同类主题里哪些作品做到了「写日常而不 low」？它们的曲名结构/意象选择/氛围处理共性是什么？如果这个选题只能保留一句词，应保留哪类句子？
4. **情感/哲理渗透**：这个选题的情感内核是什么？可在哪些生活肌理处嵌「情理钻石」——给 2-4 条候选方向（每条：嵌在什么具体物件/动作里 ＋ 一句候选闪光句）。剂量守「一点点，不能太多」：不喊口号、不说教。

追问沿用第三步招式；本模式的「要落地」换成：**「按这个方案写，曲名会是什么？给 3 个候选」**——曲名是升华度的第一道体现，也是可交叉比对的具体物。

**第四源（平台同类实况）**：搜目标选题的同类曲名，看已有同类曲是否走红——有同类爆款落地 = 受众验证；同类全为朴实白描且数据平平 = 升华空间存疑。平台实况是「大众耳朵」，权重不低于多家 AI 的「文献耳朵」。

**成本控制**：同批同方向的多选题可**合并一场调研**（问题组覆盖方向共性 + 逐选题问升华方案）；已确立方向内的续写按批调研。创作者可显式豁免并留痕。

## 方法论七步

```
① 统一问题组 → ② 多家深聊（侧重不砍维度） → ③ 逐家追问 → ④ 交叉三分区 → ⑤ 第四源补充 → ⑥ 来源留痕 → ⑦ 降级路径
```

### ① 统一问题组设计

把调研目标拆成 **5-9 个维度**，写成一组问题，**各家发同一组**（措辞可按家微调，维度一个不砍——同题共答才能交叉比对）。问题组直接决定报告质量：维度漏了，各家都不会替你补。设计时按「输出物倒推」——报告要支撑什么决策，就问什么。

### ② 多家深聊：各家侧重不砍维度

每家都过**全问题组**，但预期各家强项不同，追问方向随之倾斜（侧重影响追问，不影响覆盖）。当前实测观测（各家能力会迭代，以当次实测为准）：

| 站点 | 实测强项 | 典型独有产出 |
|---|---|---|
| 豆包 doubao.com | 结构化拆解、制作工程框架、联网检索量大 | 和声/混音工程框架类 |
| Kimi kimi.com | 外部资料检索、图片搜索、可跑代码计算，多轮考据式深聊 | 乐谱图片检索 + 音符级转写类 |
| DeepSeek chat.deepseek.com | 深度思考推理链、一手资料挖掘（官网/文献/论坛引证） | 官方一手资料 + 乐评引证类 |

能力开关各家不同：联网检索/深度思考等模式开关在发问前确认已开（位置随版本变，现场看页面）。

### ③ 逐家追问（3-6 轮/家）

首轮发问题组，之后按该家回复追问。追问招式：

- **要出处**：「这个结论的来源是什么？」——引出官网/文献/论坛一手资料
- **要量化**：「给出数值区间/逐音序列/逐段地图」——把定性转定量
- **要展开**：「X 维度再往下拆两层」
- **要反例**：「有没有与这个判断相反的证据？」
- **要落地**：「如果要复刻，这条特征怎么转成生成指令？」

轮次节奏：每家 3-6 轮起步，回复质量开始重复/空转即止。

### ④ 交叉比对三分区（核心工序）

逐维度把各家答案摆到一起：

| 分区 | 判据 | 处置 |
|---|---|---|
| **共识区** | ≥2 家独立得出一致（表述可不同，所指相同才算） | 高置信，进方案优先采用 |
| **分歧区** | 各家口径不一 | **并列呈现 + 各家原话 + 判断依据 + 处置建议**，不擅自裁决；数值类分歧通常不采信任何单值，采信方向性共识 |
| **独有洞察区** | 仅一家产出 | 标注独家来源——**往往是金矿**；可信度按来源分级单列 |

「表述不同所指相同」需要真读原文；把多种表述并列留痕（互证力更强）。

### ⑤ 第四源补充（平台实况）

多家 AI 都是「文献耳朵」，补一个「大众耳朵」源：搜索目标题材——话题视频数据 + 高赞热评 + 平台总结。热评是大众听感的一手实证；若手头有音频成品，本地实测（RMS 曲线等）可再作一个客观源，量化物理证据优先于任何转述。

### ⑥ 来源可溯留痕

报告中**原话摘录**进正文（哪家说的、原句是什么），尾部列来源清单 + **可信度分级**：

- **实锤**：多源互证 / 一手引证（官网/官方文献）
- **高共识**：多家一致但无外部文献
- **推测**：单源/听辨级——**必须标注**，不得混入前两级

### ⑦ 降级路径（不阻塞）

某家登录态失效/站点不可用/审核拒答：**双源交叉也成立**，继续推进不纠缠；单源结论按「推测」级处理并留票据。多家全灭才升级阻塞票。

## 工具链配方（ego-browser 驱动）

### 通用驱动序列

1. **导航**：ego-browser 打开站点，确认登录态。
2. **定位输入框**：按序探测 `[contenteditable='true']` → `textarea` → `[class*='input']`。
3. **注入**：`ta.focus()` + `document.execCommand('insertText', false, txt)`（React 受控组件下最稳）。
4. **发送**：`keyboard.press("Enter")`——**不要用 `page.click` 发送按钮**（actionability 检查可能卡死）。
5. **等待回复完成**：轮询回复区文本长度至稳定（两轮采样不变）/停止按钮消失/复制操作可用；联网检索轮耗时显著更长。
6. **多轮续接**：同会话直接追问；发现该家「失忆」（答非所问/重复首轮）→ 上下文已滚动，新开会话重述问题组 + 已有结论要点。

各站选择器随版本漂移：首访现场定位，定位成功后回写本节。

### 操作纪律

- **AI 文本自述不算数**：说「已检索 N 篇」不代表检索质量高——以回复中实际引用的出处密度为准。
- 家间隔离：每家独立会话，不把 A 家结论喂给 B 家冒充共识（污染交叉独立性；确需对质时明确标注「另一家观点，请独立判断」）。
- 成本意识：多家 × 多轮是重流程，先过「何时用」判据再启动。

## 陷阱速查表

| 坑 | 处理 |
|---|---|
| 流式未完成就读走半成品 | 文本长度稳定判据（两轮采样不变）再摘录；联网轮尤其慢 |
| AI 幻觉补写（无出处的「事实」） | 无第二源交叉的细节按存疑处理，标注「疑似补写，勿引用」；单源不采信 |
| 数值类各家各说各话 | 不采信任何单值，采信方向/量级共识；区间并列留痕 |
| 文风差异 | 摘录保留各家原文风格；比对按「所指」不按「措辞」 |
| 发送按钮 disabled | 刷新页面重置组件状态 → 重注入 → 验按钮 → Enter 发送 |
| 会话上下文滚动失忆 | 新会话重述问题组 + 已有结论；跨会话索取旧内容无效 |
| 登录墙/会话过期 | 降级路径；或交创作者扫码，不硬试 |
| 追问空转 | 该家轮次即止，3-6 轮是弹性区间不是硬指标 |

## 输出契约（三分区报告结构）

```markdown
# <题材> 交叉调研报告（多智能体交叉验证版）
> 调研日期/触发/方法论声明（几家几轮+第四源）/前序底座链接

## 一、调研概况与信源（表：源×轮次×特色×关键产出）
## 二~N、维度章节（每维度内：共识区/分歧区（含处置）/独有洞察区）
## 分歧处置表（项 | 家A | 家B | 家C | 处置建议）
## 应用层（配方卡/Style 指令/升华方案候选表）
## 来源清单 + 可信度分级（实锤/高共识/推测）+ 已知分歧与处置
## 待创作者拍板项（审美/版权类决策不代理）
```

报告落点：项目内的调研目录（文件名建议 `<题材>-<主题>.md`，git 留痕、跨会话可溯；目录按你的仓库约定）。

## 维护

- 各站选择器/能力开关随版本漂移：首访实测后回写「工具链配方」节。
- 新坑进「陷阱速查表」；新追问招式进第三步。
- 单实例结论不立即沉淀为规则；后续复用中验证迭代，双实例后升格条目置信度。

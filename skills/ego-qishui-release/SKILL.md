# 汽水合作平台发行自动化（三步向导）

> 平台是抖音系 Semi Design 组件库，表单结构以 `x-field-id` 属性为准。
> 依赖：`ego-browser` + `music.douyin.com` 登录态。登录态过期时用 `handOffTaskSpace` 交用户扫码——这是物理边界，停等不是失败。
> 验证码：可选依赖 `sms-code-reader`（chat.db 直读）。没有它时，验证码环节交给用户报码，其余流程照常自动化。

## 发布前置物料（缺一不可）

| 物料 | 要求 |
|---|---|
| **发布前置查重** | 排期或发布任何专辑前，先在 `console/songs` 搜曲名确认未发行过。**发行状态的唯一权威是 `console/songs` 搜索**，不是台账、不是直链标记。搜**发行名/资产名**而不是工程名（工程名/词牌名搜索会假阴性）；空结果必须跑对照组（搜一首已知已发行曲）排除搜索功能异常；同名结果须核对 songId/专辑归属，同名 ≠ 同一资产（平台允许同名多版本）。 |
| **当日额度** | 每日最多发布 10 首（跨专辑共享，自然日 00:00 重置）。满额时：空表单「上传添加歌曲」入口直接拦截；直链预绑定表单可打开可填写，但「下一步」被 toast 拦截——**满额日只能建到 step1 完整态停靠，跨日续跑**。 |
| **网络环境** | 上传与电子签对代理网络敏感：实测代理下音频上传反复「上传异常」，关代理直连后一次成功。发布全程用直连；若用 VPN，先断开并检测 DNS/路由残留（见 `astrill-control`）。 |
| **音频文件** | wav，≤200MB。生成平台下载直传即可，通常无需母带或重采样。 |
| **歌词** | 演唱曲必填：>80 字且行数 >1；纯音乐可空。⚠️ **平台校验只查长度/行数、不查内容对不对**——长度合规不代表歌词正确，内容正确性靠提交后的歌词核验（见「QC 门 4」）。 |
| **专辑名 + 介绍** | 介绍必须 ≥2 行（单行会被「行数需大于1」拦截）。 |
| **封面** | 平台内置「智能封面」生成器（描述 ≤50 字、每日 20 次额度），无需自备图。 |
| **登录态** | 合作平台需扫码登录；过期则 `handOffTaskSpace` 交用户。 |
| **浏览器实例** | 发行前主动重启 ego-browser。电子签组件对内存压力敏感：实测内存压力下签署组件持续不渲染，重启后连续多首零障碍。重启成本 ~30s，故障成本 40min+，代价不对称。 |
| **视觉模型** | 发布自动化必须用视觉模型执行——签约卡选中态、跨域 iframe 内按钮、验证码弹窗定位都依赖截图判断；纯文本模型会点错位置。 |
| **授权证明** | 选择「独家代理发行」时必须上传（zip/jpeg/jpg/png/bmp/pdf ≤200MB）：权利文件、版权证明、平台截图均可。审核可能以「授权证明有效性不足」拒绝，可在 `console/songs` 行内「修改」补材料后重提。 |
| **无人值守预检** | 屏幕未锁（锁屏是物理阻塞）、调试端口未被占用、会话判活（cookie 未过期 ≠ 会话活——服务端可主动吊销）。遇风控信号（会话吊销、签署持续故障）停自动化转人工，勿高频重试。 |

## 入口

`music.douyin.com/console/publish` → 点「发布全曲」（用真实鼠标 click；DOM `.click()` 有时不触发）→ 三步向导：**1 上传作品 → 2 授权作品 → 3 签署协议**。

## 步骤 1 · 上传作品

### 为什么需要容器标记法

表单是每首歌一个「块」，添加歌曲后 DOM 中每块的字段重复出现。任何全局 `querySelector` 都会命中**文档序第一个块**——批量上传时后续歌曲的文件、标题会反复覆盖第一块。对策：先把目标块容器打上临时属性，再用组合 CSS selector 精确操作。

```js
async function fillTrack(num, name, marker, lyrics) {
  // 1. 点「点击添加歌曲」（首曲跳过）
  // 2. 标记新块：找 placeholder==='请输入' 且 value 为空的 input，
  //    向上爬到含「音频文件」的祖先，p.setAttribute('data-blk', marker)
  // 3. 音频：uploadFile(`[data-blk="${marker}"] input[type="file"][accept*="audio"]`, wavPath)
  // 4. 标题：容器内 input[placeholder="请输入"]，native value setter + dispatch input 事件
  // 5. 歌词：容器内 textarea，同样注入；填完回读 value.length
  // 6. 移除 data-blk 属性
}
```

要点：
- React 输入组件必须用 `Object.getOwnPropertyDescriptor(HTMLInputElement.prototype,'value').set` + `dispatchEvent(new Event('input',{bubbles:true}))`，直接赋 value 不生效。
- `uploadFile` 的 selector 也必须带 `[data-blk=...]` 前缀，否则命中第一个块。
- 每块含 **4 个** audio file input（完整版/片段等），file input 数 ≠ 块数；数块用可见标题框数（`offsetWidth>0`）。

### 全局设置（一次性）

按顺序：AI 声明点「是」→ AI 工具下拉选择实际使用的生成平台（**如实申报**，选错属虚假声明有审核风险）→ 音乐类型点「原创」叶子节点。
「请选择音乐类型」是该字段的**常驻 label 文案**，不代表未选中；判断状态要看 `.douyin-music-radio-checked`。

### 🛑 歌词框 / 介绍框定位（P0：必须用互斥正则分类）

**不要用子串排除定位文本框。** 曾有一次真实事故：一行定位代码在一次批处理中扩散 8 首，7 首静默上线。

缺陷机理（三段式）：

1. 子串排除有隐藏前提——只有计数器文本自含排除串时排除项才生效。歌词字数不以 0 结尾时（如 `793/10000`），`!includes('0/10000')` 恒真，**排除项形同不存在**。
2. 于是向上第 5 层祖先里的介绍计数器成了唯一命中项——介绍框 `0/1000` 命中、歌词框被判为介绍框，**介绍文案整段覆盖真歌词**。
3. 长度闸写在匹配之后等于没有——匹配已错，后面的长度检查救不回来。**长度闸必须在匹配之前。**

改用互斥正则分类：

```js
const classify = (ta) => {                        // 对每个 textarea 判型
  let el = ta;
  for (let k = 0; k < 8 && el; k++) {
    el = el.parentElement; if (!el) break;
    const t = el.innerText || "";
    if (t.length > 700) break;                    // 长度闸在匹配之前
    if (/\d+\/10000/.test(t)) return "lyrics";    // 歌词：任意计数 /10000
    if (/\d+\/1000(?!0)/.test(t)) return "intro"; // 介绍：/1000 且后一位非 0
  }
  return "unknown";
};
// 只写 kind==="intro" 的框；未命中 → NO_INTRO_BOX 报警中止，绝不猜
```

两个要点：**互斥**（`(?!0)` 负前瞻把 `0/10000` 里的 `/1000` 前缀排除，两类正则不可能命中同一计数器）＋ **未命中即停**（unknown 时报警中止，不退回位置/长度启发式）。

**写后回读守卫（必带）**：注入前记录 `lyricsLenBefore`，注入后回读**歌词框长度**——发生任何变化即报警中止（说明写错框了）。⚠️ 只看「下一步」是否推进不算验证：事故批里中招曲的「下一步」全部正常推进。

### 批量字段注入的扩散纪律

同一处字段定位缺陷在批处理中是**乘法级扩散**（1 行代码 → 8 首出错 → 7 次编辑 + 7 次重签 + 7 个验证码）。三条纪律：

1. **先跑 1 首再放量**：首曲以「歌词长度 == 词稿长度」验证通过后才继续，不以「流程走得通」作为放量依据。
2. **批量后全批逐首抽查**：收官时逐首核字段长度＋首行（不必重填）——若在收官节点抽查任一曲，即可当日拦下全部问题曲。
3. **字段类操作一律带写后回读断言**：回读比对长度，而不是看按钮是否推进。

**「校验过」≠「内容对」，「下一步能点」≠「字段对」**——唯一可靠判据是把写进去的内容/长度回读出来与词稿比对。

### 作者字段（tags 组件）

表演者/词作者/曲作者是 tags 选择器，`input.value` 恒空是常态。点各 field（`[x-field-id="songs[N][authorArtists|lyricistArtists|composerArtists]"]`）内的「添加自己」写入账号艺人；验证方式是检查 field 容器 innerText 是否含艺名，而不是 `input.value`。
账号艺人档案已配置时，新块的三个作者字段会自动带出，填块前先检查，避免重复添加。

### 专辑信息

- **专辑名**：`input[placeholder="请输入专辑"]`
- **专辑介绍**：唯一特征是计数器 `/1000` 且后一位非 0（`/\d+\/1000(?!0)/`）；定位后先读现值，为空或垃圾内容才灌入；灌后回读长度。
- **封面描述**：只在点开「智能封面」弹层**之后**、在**弹层内**找 textarea（弹层 = 含「生成封面」按钮的固定定位容器）。**严禁在全页面模糊找空 textarea**——歌词框可能为空且会被污染。
- 通则：专辑级字段与曲目块一样用容器特征锚定，禁用位置启发式。

封面生成：填描述（≤50 字，用固定风格前缀开头保证出图风格一致——前缀缺失直接导致风格跑偏，生成前回读确认）→ 选版式 → 「一键生成封面」→ 等 15–30s → 「使用封面」可点后点击。验证：封面区出现 `byteimg` 图片。⚠️ 弹层形态随版本变化（有/无「模板」选项两种形态都实测存在），按现场表单操作，勿预设。

### 推进「下一步」的等待纪律

音频上传后平台要做**服务端转码**。转码未完成时点「下一步」会报「平台内发行表单填写错误，请检查」（误导性极强——字段其实都对）。纪律：**主动轮询「音频检测中」消失（≤60s）再点下一步**，优于「点了失败再重试」。成功标志：侧栏步骤条的「授权作品」进入 process 状态。

保存草稿可随时落库，刷新后从 console/publish 的「继续编辑」入口恢复（注意：恢复草稿会重置全局设置，复查 AI 声明/工具/音乐类型三项）。

## 步骤 2 · 授权作品

### 签约模式三卡片

独家代理发行（3年）/ 独家授权（3年）/ 非独家授权（3年）。

- **独家代理发行**是常见默认：全球分发 + 流量包。**必须上传授权证明**（平台新规约）。
- **独家授权（3年）**同属全链可发行，且**免授权证明上传、免必填**——直链快道路径只出独家系两卡时，这是最快可过路。
- **非独家授权（3年）**：step2 的「艺人信息补充/制作人/歌曲信息补充」区整个不渲染（均为代理场景专属字段），免全部必填直接下一步；step3 协议弹窗直挂、免勾 checkbox。
- 签约模式是商业条款，最终按创作者每批拍板选择；自动化不要替人决定。
- 选中态**没有 selected class**（只有边框/背景变色 + 对勾图标），DOM class 检测会误判——用 CDP 截图视觉确认。

### 必填项

- 授权比例默认 100%；词/曲作者真实姓名自动带出。
- **制作人**：每曲必填，点「添加自己」带出艺名。⚠️ 直链预绑定路径的表单结构不同——该路径「添加自己」点击可能无响应但制作人非必填，两路径不要互相套用。
- **艺人主页链接（必填）**：4 条平台链接（QQ音乐/酷狗/酷我/网易云），默认「有主页链接」。艺人未入驻外站时逐条切「无主页链接」即可过，**勿编造 URL**。链接下拉在视口外时坐标点击必落空——先 `scrollIntoView` 或 wheel 滚动到位；每轮操作 ≤2 个防 `Runtime.evaluate` 超时。

### 发行前署名核验

进入步骤 2 先数「艺人信息补充」区的艺人行数——**必须等于预期署名人数**。只有一行而预期双人 → **停点**：回到生成侧核实音色挂载，不可补救则如实按 solo 发行并记录「署名未生效」；**严禁硬发**（已发行后表演者不可回补）。

## 步骤 3 · 签署协议

### letsign 渲染触发条件

签署组件（letsign 跨域 iframe）的渲染触发条件 = **先勾选发行表单底部的 2 个协议 checkbox**。未勾选 = 组件从未加载（曾因此误判「环境渲染失败」连续失败）。
**先读态再补勾**：初始态可能是 `[false,true]`，盲目全点会把已勾的第 2 个点掉；勾齐 `[true,true]` 后等 3-5s 让弹层渲染。
⚠️ 非独家路径是例外形态：协议弹窗直接渲染、免勾 checkbox——按现场表单形态选姿势。

### 两种自动化链（按工具链选，勿跨链套用）

| 链路 | 姿势 |
|---|---|
| **快照桥接**（ego-browser 原生工具层） | `page.snapshot()` 输出**含 iframe 内节点**，`page.click("@ref")` / `page.fill("@ref", code)` 可跨域操作。全链零 attach、零坐标：点「签署」→ 点「获取验证码」→ fresh snapshot 取 textbox ref → 填码 → 点「确定」。 |
| **OOPIF 直连**（CDP 直连） | 宿主页坐标点击对 letsign 跨域 iframe **完全无效**（`Input.dispatchMouseEvent` 多点零响应，AX 树也不收集 iframe 内节点）。正解：`Target.attachToTarget(iframe targetId, flatten=True)` 拿 sessionId → `cdp(..., session_id=xxx)` 直达 iframe 上下文 `Runtime.evaluate`：签署/取码/填码/确定全链零坐标 JS click。每张表单有新 letsign target，attach 后存 sessionId 备用。 |
| **系统级点击**（最后通道） | `osascript` System Events 的 click 等价真人鼠标，可穿透跨域 iframe。弹窗每次渲染位置漂移——**现场截图现场算坐标**，勿复用上轮坐标。 |

⚠️ CDP 直连下 `Runtime.evaluate` 复合表达式偶发挂起、短表达式正常——根因是 daemon 会话消息路由问题，不要在表达式复杂度上徒劳优化。

### 验证码

- 点「获取验证码」→ 等 40-60s（手机→Mac 同步延迟）→ 读码 → 填入 → 确定。
- **时间窗判定**：只接受 0-270 秒内的码；超窗 = STALE 丢弃。同一签署单提交失败后**该单验证通道锁定**（新码填入「确定」恒 disabled）——处置是刷新重走全链换新签署单（~5-8min），继续烧码更贵。
- **入库延迟是常态**：短信已到但 DB 晚可见很常见（实测最长 ~3min）。短时间无新码**不重复触发**（重触发=发新码、旧码作废、限流更紧），延长轮询窗（如 18×15s）即可。
- 填码用 native setter + `input` 事件（**不加 change**）→ 轮询「确定」`disabled=false`（通常 1s）→ 立即 click。**勿把填码+确定合并为单次 evaluate**（React 状态未更新即提交）。
- 成功判定：弹窗「签署成功」或页面跳转。fill/click 执行成功后 evaluate 抛错 ≠ 签署失败；最终以 `console/songs` 状态为准。

### 签署陷阱

| 坑 | 处理 |
|---|---|
| checkbox 未勾 = letsign 永不渲染 | 先勾 2 个 checkbox，再等弹层 |
| ref 跨回合/跨页失效 | 每次操作前 fresh snapshot 现取 ref |
| 弹窗半关遮罩拦截点击 | reload 重置组件状态；代价=草稿可能丢失需重填 |
| 读到旧码 | 时间窗过滤，STALE 必重触发，严禁输入旧码 |
| 后台批量脚本并发同一 taskSpace | 签署类长流程禁用后台批量脚本，逐首串行 |
| 签署白屏三形态（点击不落地 / iframe 长时不挂载 / 协议区白屏） | 三轮均非 reload 可解——第一轮排查后即人工收口，勿烧第三轮 |
| 老发行单签署回调故障 | 跨日旧单反复签署不落地，同期新单正常——弃单开新发行单（备用候选先过 QC）或人工收口 |
| 协议面板静默不渲染 | 面板是 contract API 数据驱动：应答「未登录/合同创建失败」时无提示无报错。判读法：**letsign 零请求 + 协议面板组件不在 DOM = 上游无数据**，查 contract API 应答体与登录态，不是组件故障 |
| letsign 会话级缓存 | 一次意愿认证成功后，其他停靠表单可能免二次验证码——但**不保证**（有反例），时间预算按「可能免码，以现场为准」做 |
| 停靠表单 tab | 表单页在 tab 内可停靠过夜，刷新/关闭即丢；URL 含 `getCompletePublishRouter` 可识别，勿关勿刷 |

## 提交结果核验

签署完成页面自动跳转 `console/albums/detail/<albumId>`，成功标志：「音乐正在审核中，暂不支持修改」+ 逐曲状态「发行审核中/已发行」。

复核入口：`console/songs` 搜索逐曲查询，状态枚举：`已发行 / 发行审核中 / 已下架`。前台搜索页 SPA 在自动化环境常不渲染——可搜性核验一律走 console；空结果必跑对照组。

**albumId 获取路径**：歌曲管理搜曲名 → 行内「查看详情」得 `console/songs/detail/<songId>` → 详情页专辑名链接即 albumId。

⚠️ 「审核中」只说明提交成功，不代表歌词字段正确——提交后必跑 QC 门 4。

## 发行 QC 四道门

| # | 门 | 时点 | 判据 | 不过的处置 |
|---|---|---|---|---|
| 1 | 静音 | 发起发行前 | 无 >4s 静音段 | 重新生成，不硬发 |
| 2 | 尾部淡出 | 发起发行前 | 尾部 12s RMS 渐弱收尾、非平直 | 重新生成 |
| 3 | 名与署名核验 | 表单在场时 | 预填名 == 工程曲名；艺人行数 == 预期署名人数 | 名漂移在表单期手改回（input 可编辑：native setter + 读回验证）；署名不符停点 |
| 4 | 歌词核验 | 提交后 / 当批收官 | 平台歌词字段 == 工程词稿 | 走「修改」路径重注入 |

### 门 1-2 · 音频双判据

```bash
# 判据1：检测 >4s 静音段（应零命中）
ffmpeg -i in.mp3 -af silencedetect=noise=-45dB:d=4 -f null - 2>&1 | grep silence
# 判据2：全曲逐秒 RMS，取尾部 12 行看淡出曲线（应渐弱收尾非平直线）
ffmpeg -i in.mp3 -af "astats=metadata=1:reset=1:length=1,ametadata=print:key=lavfi.astats.Overall.RMS_level" -f null - 2>&1 | grep RMS_level | tail -12
# 修复配方：压缩所有 >4s 静音至 1.5s（保留呼吸感）
ffmpeg -i in.mp3 -af "silenceremove=stop_periods=-1:stop_duration=4:stop_threshold=-45dB:stop_silence=1.5" -c:a libmp3lame -q:a 2 out-fixed.mp3
```

健康尾部：主体 -13~-18dB → 递减淡出（如 t-2s -17.7 → t-1s -26.1 → 终 -34.4dB）。「戛然而止」= RMS 维持 -15~-18dB 平直线直至终点，是截断风险。

**QC 音频下载通路**：打开发行表单（**仅打开不提交不消耗发行单**）→ 表单打开即自动加载 douyinvod 音频 → 用 `performance` resource entries 抓签名直链 → `curl -o qc.mp3` 下载 → 跑上述双判据。生成侧也可从播放器触发播放后抓直链。

**紧急豁免**：仅在创作者显式紧急令下可跳过门 1-2，且必须当日留痕三要素：豁免范围（逐首）、原因与令出何方、「平台若拒收留票」风险自担。无令不得自行豁免。**豁免只及门 1-2（音频），门 4 歌词核验不可豁免**（不耗发行单、不依赖验证码）。

### 门 4 · 提交后歌词核验

**为什么单设一道门**：歌词是平台侧元数据，**音频对不代表歌词对**——音频可以按工程词稿唱对，而「展示歌词」字段是错的；平台校验只拦「太短」、拦不住「内容错」。真实事故中，被介绍文案整段覆盖的「歌词」大多通过了长度校验并静默上线。

**执行时点**：逐首提交后立即核；批量发行 = 当批收官时逐首核。

**快速判据（零成本筛查）**：
- 歌词字段出现介绍文句式 → 肯定错。
- 长度 <200 且无 `[` 段落标记 → 可疑（工程词稿通常 700-900 字、含段标）。
- 快速判据只做筛查，闭环以长度/首行与词稿逐字比对为准。

**核验配方**：`console/songs` → 行内「修改」→ 编辑表单 `complete-publish-astra?song_id=<songId>` → `classify()` 取歌词 textarea → 回读长度＋首行，与工程词稿比对。修改路径不计入每日额度；歌词框可编辑（`maxLength=10000`）。

**修复链**：编辑表单 → 重注入工程词稿 → 把被顶掉的介绍文案归位介绍框 → 三步向导 → 逐首重新签署＋独立验证码 → 提交。验收判据 = 修复后长度 == 原始预填长度（长度全等才证明文本同源）。⚠️ 审核通过前线上仍显示旧歌词 → 立审核后复核票据。

## 妙响 issuedId 直链快道

适用：妙响平台产出的曲（有 `complete-publish-astra` issuedId）——**此路径无需上传音频**，表单预绑定音频+预填歌词+表演者。

1. **打开发行入口**：`https://music.douyin.com/console/complete-publish-astra?enter_from=astra&issuedId={id}`。⚠️ **正格式无 `/publish` 前缀**——带前缀会路由到「选择类型」页并丢失 issuedId 上下文，表现为全空表单假象。
2. **预填名终核**：表单预填标题逐字核对工程曲名。上游防线是在生成侧注入「曲名定为《X》」显式句；核对源是你的「工程曲名↔资产名↔issuedId」映射表。
3. **表单填写**：点「原创」→ 是否纯音乐按实际选 → 削波提示点「一键修复」→ 下一步。
4. **授权**：该路径 step2 通常只出独家系两卡（无非独家）；选**独家授权（3年）= 免授权证明 + 免必填**，是最快可过路。选独家代理则按物料表备授权证明。艺人主页链接下拉切「无主页链接」可绕过（勿编造 URL）。
5. **电子签**：按步骤 3 的链路表执行。
6. **验证码**：可选依赖 sms-code-reader；失败 fallback = 人工报码。
7. **批量节奏**：每首提交后到下一个验证码触发之间有 ~6min 空窗，可用于「回收已完成页建下一单 + QC 预核」，与短信触发间隔并行、零额外耗时。

### 直链路径陷阱

| 坑 | 处理 |
|---|---|
| 表单推进失败（下一步无效） | 先读校验 toast（如「请填写艺人主页链接」），勿反复换点击姿势 |
| reload 后全局选择被重置 | 音乐类型/纯音乐需重选；音频/歌词/标题/封面保留 |
| 直链消耗 ≠ 本资产已发行 | 发行状态唯一权威 = console/songs 搜索（空结果跑对照组） |
| 直链预绑定表单 step2 无非独家 | 直链快道与非独家互斥；需非独家时走「发布全曲」空表单路径 |
| 已耗 issuedId 重建表单 | 提交会撞「不能重复发行」墙（只空烧验证码，不产生重复单） |

## 收尾登记

提交成功后在你的作品台账回写最小四字段：**发行日期 / 平台状态 / 曲名 / songId（或 albumId）**；若你有平台数据单与审计快照，一并更新。收官时逐首过门 4 歌词核验；随后核对当日额度，未满则按创作/发行计划继续。

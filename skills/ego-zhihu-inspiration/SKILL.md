# ego-zhihu-inspiration · 知乎灵感采集

> **定位**：用 ego-browser 逛知乎，为音乐创作采集高赞真实故事/人生时刻/问题句式 → 灵感候选表（时刻/情绪内核/升华方向/溯源）→ 进创作选题链。
> **前置依赖**：`ego-browser` + 知乎登录态（失效时交创作者扫码，不硬试）。
> **版权边界（硬纪律）**：素材只做**指向启发**（选题/情绪内核/共鸣面），歌词**一律独立创作**；**零文本借用、零叙事复述**——写词后由检查链核 8-gram 零复述。

## 何时用 / 不用

**用**：
- 新批次选题调研的**真人一手面**——与 `ego-multi-ai-research`（创作调研模式）分工互补：AI 多家给「升华方案与表达技法」（文献耳朵），知乎给「真实故事与共鸣铁证」（大众耳朵）
- 创作者指路「去知乎找灵感」
- 已有方向缺「它真的发生过」的素材——高赞 = 成千上万人用点赞投过票的真实

**不用**：单点事实核查（web 搜索更快）；市场/趋势判断（用 `music-trends-report`——知乎是素材矿，不是市场数据源）。

## 方法论（采集 → 筛选 → 转译 → 落链）

### ① 登录探针（第一步·必做）

打开 `zhihu.com` 首页 → 读 header/首屏 innerText：含「登录/注册/立即登录」= **未登录**（交创作者扫码）；无登录按钮且可见推荐流 = 登录态 ✓。未登录也能看部分内容，但高赞回答全文与搜索完整结果需要登录态。

### ② 三入口采集（按价值排序）

| 入口 | URL | 预期 | 定位 |
|---|---|---|---|
| **A 热榜** | `zhihu.com/hot` | 低（新闻占绝对多数） | 快扫——情感位有就捞、没有就走 |
| **B 搜索批量**（主矿） | `zhihu.com/search?type=content&q=<词>` | 每词约 8-10 问题 | 抓 `a` 标签中 href 含 `/question/` 的链接（标题 + 问题 ID）；结果是 answer 级链接，取 `<qid>` 即可 |
| **C 问题详情**（金矿） | `zhihu.com/question/<qid>` | 每问题 6-30KB 全文 | innerText 全文落盘——含标题/关注数据/回答列表（作者 + 「等 X 万人赞同」+ 正文）；高赞回答是完整故事 |

**搜索词设计**：每词 = 「**情绪象限 + 真实经历标记**」双要素——如「人生低谷 真实经历」「成年人的崩溃瞬间」「陌生人的温暖 故事」「暗恋 遗憾 真实」。真实经历标记把搜索面从「观点讨论」拉向「一手叙事」——素材需要的是**发生过的故事**，不是抖机灵的段子。
- 词库按当期方向象限定制；创作者新的选题方向 = 搜索词的源头。

### ③ 候选提取（素材 → 选题·四要素）

逐条高赞回答提取：

| 要素 | 提取什么 | 好素材判据 |
|---|---|---|
| **时刻** | 一句话：什么时候发生了什么 | 具体可拍（切菜割手/卖报第一天开口/5 点被麻雀吵醒）——**纯观点/争论贴不选**（没有时刻就没有歌） |
| **情绪内核** | 情绪弧线（撑→破防→暖？窘迫→被托住？） | 有转折；高唤醒词根（心动/痛/憾/燃/不甘/羞耻/决绝） |
| **升华方向** | 从生活载体升到高级意象域 | 载体有延展空间（「湿被子」→负重域；「茶是热的」→孤而不惨） |
| **溯源** | 赞数 + 作者 + 链接 + 日期 | 信源分级：**A** = 高赞一手真实经历（1k+ 赞）｜**B** = 中赞/分析向｜**C** = 问题标题句式（大众提问面→曲名方向/结构参考） |

**与存量对照**（每批必做）：候选逐条 vs 已发行/在库选题——标注「新增／重合互补／邻接」；邻接要显式标风险（交创作链定夺弃/改角度）。

### ④ 版权边界（硬纪律）

- 素材**只做指向启发**：选题/情绪内核/共鸣面——歌词**一律独立创作**。
- **零文本借用、零叙事复述**（防改编权风险）——写词完成后由检查链核 **8-gram 零复述**。
- 与 remix/公版改编线不同：公版线有引用母本的授权阶梯；**本线零文本借用**——知乎故事连「原句引用」也不做。

### ⑤ 报告落盘 → 拍板

报告落项目调研目录 `zhihu-inspiration-<date>.md`：

1. **采集概况**（入口×规模×结果——含弃用记录）
2. **灵感候选总表**：A 高赞叙事启发类（素材溯源·赞数 ｜ 时刻一句话 ｜ 情绪内核 ｜ 升华方向初判）＋ B 问题标题句式类（原问题标题 ｜ 可用点）
3. **与存量候选合并对照**（重合/新增/象限偏离）
4. **推荐组合**（供拍板——沿批级声线配平等纪律）
5. **来源清单**（全部链接 + 落盘路径）
6. **待拍板项**（邻接风险/角度选择等——审美裁决不代理）

## 工具链配方（ego-browser·四段脚本模式）

```js
// 通用起手（space 名带任务语义：zhihu-<任务>-<date>）
const task = await taskSpace("zhihu-explore-<date>");
const page = (await task.pages())[0] || await task.newPage();

// ① 探针
await page.goto("https://www.zhihu.com/", { timeout: 90000 }); await sleep(8000);
// → header 无「登录/注册」= 登录态 ✓

// ② 热榜：goto "https://www.zhihu.com/hot" → sleep 9000 → body.innerText 落盘

// ③ 搜索批量（主循环）
for (const q of QUERIES) {
  await page.goto("https://www.zhihu.com/search?type=content&q=" + encodeURIComponent(q), { timeout: 60000 });
  await sleep(6500);
  // evaluate: 抓 a[href*="/question/"] 的 innerText（>12 字）+ href.split("?")[0]，去重取前 12
  await sleep(1500);
}

// ④ 问题详情
for (const qid of QIDS) {
  await page.goto("https://www.zhihu.com/question/" + qid, { timeout: 60000 });
  await sleep(7500);
  // evaluate: document.body.innerText 全文 → 落盘
  await sleep(1500);
}
```

**关键参数**（实测）：搜索 6.5s/词、详情 7.5s/篇、词间 1.5s（知乎 JS 重，节奏留给渲染）；落盘到项目临时目录；全文落盘后**离线提取**（正文按换行分段，赞数在作者行「等 X 万人赞同」形态）。

## 陷阱速查表

| 坑 | 处理 |
|---|---|
| **「故事」Tab = 盐选网文区** | 首页「故事」入口实为虚构网文连载——与「真实故事」素材边界不符，**弃用**（记录在案、不重试、不绕路） |
| 热榜远音乐象限 | 新闻占绝对多数、情感位稀缺——快扫低预期，别在热榜耗采集预算 |
| 搜索结果是 answer 级链接 | 抓到 `question/<qid>/answer/<aid>` 形态——**取 `<qid>` 按问题级采集**即可 |
| 登录态失效 | 探针查 header 登录/注册按钮——失效即交创作者扫码，不硬试 |
| 赞数读取 | 从问题详情 innerText **作者行**提取：≥1 万 = 「等 X 万人赞同」；<1 万 = 「N 人赞同了该回答」——勿依赖 DOM 数字节点 |
| 搜索词含「真实」不保证一手叙事 | 议论式回答仍会出现——靠 ③ 候选提取的「纯观点/争论贴不选」判据拦住 |
| 采集时点影响内容 | 深夜时段情感内容占比或更高（推测级观察，未对照；不因此限定采集时段） |
| 高赞回答混入「显示全部」截断 | innerText 可能含「…显示全部」折叠态——正文提取时跳过含「显示全部」的段落行 |

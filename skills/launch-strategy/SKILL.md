# 专辑上线计划与变现策略（launch-strategy）

> **定位**：从「生成完成」到「上线变现」的全流程编排。
> **核心原则**：新人优先蹭热度（借已有搜索池），再逐步建立自有搜索资产。
> **前置条件**：专辑已通过创作审查 + 生成完成（音频已产出并过 QC，或 .wav 已下载）。

## 触发词

- **上线计划 / launch plan**：为专辑生成 `launch_plan.md`
- **蹭热度 / 冷启动**：制定曲名蹭热度策略
- **变现**：规划变现路径与优先级
- **分发策略 / 分成**：平台发行与收益规划

## 适用范围

- ✅ 专辑级上线规划（选曲排序 + 上线节奏）
- ✅ 曲名蹭热度策略制定
- ✅ 变现路径选择（播放分成 + 短视频 BGM 联动）
- ✅ 发行侧指标参考
- ❌ 不适用于趋势调研（用 `music-trends-report`）
- ❌ 不适用于 Prompt 创作（用 `music-creation-workflow`）
- ❌ 已停用的内容侧推广线不纳入新计划（历史方案只作参考）

## 工作流（4 Phases）

### Phase 0：确认前置条件

| 检查项 | 要求 |
|--------|------|
| 生成 | 已完成（音频产出 + QC：时长达标 / 无异常静默 / 尾部真淡出；或 .wav 已下载） |
| 母带处理 | 仅当平台允许替换音频时适用（`audio-mastering`，-14 LUFS）；平台锁定音频则跳过 |
| 曲名确定 | 已通过蹭热度评估 |
| 商用授权 | 确认目标平台的商用条款；平台素材禁用（红线） |

### Phase 1：蹭热度策略（详见 `references/trending-tactics.md`）

为专辑每首曲目制定：

1. **曲名蹭热度分析**：曲名对标的已有高搜索量关键词（食材/地名/场景/流行语）
2. **BGM 适配垂类**：旅行随拍 / 萌宠变装 / 舞蹈翻唱等（影响歌曲设计与副歌位置）
3. **搜索池分层**：主词池（蹭外部热度）+ 品类池（后缀占位）+ 场景池（通勤/深夜/旅行等长尾）；避免只蹭单一词
4. **重名检查**：项目全库扫描零命中；避免与已知热门歌曲同名

> 已停用的内容侧推广动作（话题标签挂法、内容投放等）不纳入新计划；历史方案只作参考。

### Phase 2：上线节奏规划

按 4 周节奏分批发布（选曲排序参考）：

| 周 | 选曲原则 |
|----|---------|
| Week 1 | **蹭热度最强的歌** |
| Week 2 | **SEO 最强的歌**（精准命中热搜词） |
| Week 3 | 同名主打 + 梗歌 |
| Week 4 | 其余曲目陆续发 |

> 平台若有独家/首发规则，按平台协议调整；不把「同时发」当作互相带量的保证。

### Phase 3：变现路径规划（详见 `references/distribution-channels.md`）

**现役主路径**：

1. 流媒体播放分成 + 短视频 BGM 联动（最快见钱）。

**历史/暂停项（只作参考，不纳入新计划）**：

2. 平台音乐人认证流量助推（按平台当前政策）
3. 付费投放小额测试（按平台当前政策）
4. 海外分发（按目标平台协议）
5. 商单（依赖内容运营，按项目定位）

### Phase 4：输出 `launch_plan.md`

使用 `references/launch-plan-template.md` 标准模板，输出到专辑目录。

## 关键指标速查

| 指标 | 阈值 | 影响 |
|------|------|------|
| BGM 播放 | < 30 秒 = 0 收益（按平台规则） | 副歌尽量在 15 秒内出现（BGM 分成计数线） |
| 完播/有效收听 | 平台口径不一 | 前 30 秒设计决定留存；按平台数据校准 |

---

## 常见坑速查

| 坑 | 规避 |
|------|------|
| 免费版不可商用 | 确认目标平台的商用授权；必要时升级套餐 |
| 刷播放量 | 结算清零 + 封号 |
| 封面有多余文字 | 审核拒（通常仅曲名 + 艺人名） |
| AI 披露缺失 | 按发行平台要求勾选 AI 披露，不勾选可能下架 |

# Music DNA Extraction / 音乐风格 DNA 提取

> **核心目标**：从历史高热度标杆歌曲中提取可量化的风格 DNA，为新专辑提供精准的创作参数。
> **核心原则**：证据驱动（查真实 BPM/调式/编曲数据，不靠印象）、并行采集（多个后台调研 agent 同时执行）、交叉验证（跨歌找共性分布，不只看平均值）。
> **法律边界**：提取的是**风格 DNA**（BPM 区间、调式偏好、乐器编配模式、歌词意象词频），不是旋律/歌词/曲名。所有 Style 配方与最终作品 100% 原创。

## 触发条件

- 新专辑企划前，需要深度借鉴某类型的标杆歌曲
- 用户说「提取 DNA」「DNA extraction」「标杆分析」「风格基因提取」「深度借鉴」
- 从自建的历史标杆池报告选定类型后

## 何时不使用

- **单首歌曲创作** → 直接用 `music-creation-workflow`
- **周期性趋势调研** → 用 `music-trends-report`
- **已有 DNA 报告的专辑迭代** → 直接参考已有报告，跳过提取

## 工作流程（5 步）

### Step 1：确认目标类型 + 标杆歌曲池

**输入来源**：
- 自建历史标杆池报告（按类型筛选）
- 自建近期趋势报告（补充当前爆款）
- 用户直接指定标杆歌曲

**选择标准**：
- 8-12 首标杆歌曲（太少不够统计，太多调研成本高）
- **少于 8 首时**：提示样本不足，不据此下类型级结论（最多做单曲/小样本观察）
- 覆盖该类型在不同年份、不同平台、不同艺人维度的代表
- 优先选跨年上榜次数多的歌（历史验证过的）

**输出**：标杆歌曲池表格（歌曲名/艺人/上榜年份/上榜次数/类型标签）

### Step 2：并行调研每首歌（每 2 首派一个后台 agent）

**关键操作**：每 2 首歌一个 `general-purpose` 子代理，用 Agent 工具后台并行派发（`run_in_background=true`，同一轮消息里全部发起）。使用 `references/search-prompt-template.md` 中的标准化 prompt 模板。

```
# 分组示例（10 首标杆 → 5 个 agent）
Agent(subagent_type="general-purpose", run_in_background=true,
  description="DNA 调研 song1 / song2",
  prompt=<把 references/search-prompt-template.md 模板内容替换 {song_1} {song_2} 后传入>)
```

**每个 agent 调研 7 个维度**（详见 `references/dna-dimensions.md`）：

| 维度 | 调研内容 |
|------|---------|
| BPM | 精确值（多源交叉验证） |
| 调式 | Key + 大调/小调 + 和弦走向 |
| 乐器编配 | 完整乐器清单 + 进入时序 + 编曲哲学 |
| 曲式结构 | 段落划分 + 时间戳 + 结构类型 |
| 歌词意象 | 主题 + 12-15 个具体意象词 + 押韵模式 + 句长 + 金句 |
| 制作工艺 | 制作人/录音/混音/母带 + 音色处理风格 |
| 情绪有效性 | 为什么这首歌能治愈/打动听众？ |

**等待所有 agent 完成后**：后台 agent 完成时会自动回传结果，逐一汇总；也可在 prompt 中约定让各 agent 把调研结果落盘到项目调研目录（如 `dna-raw/<song>.md`），完成后统一读取。

### Step 3：跨歌综合（Synthesis）

**核心方法**：不是取平均值，而是看**分布**。

| 维度 | 综合方法 |
|------|---------|
| BPM | 统计每首歌的精确 BPM，画出区间分布图（如「60% 在 60-70 区间，30% 在 77-85 区间」） |
| 调式 | 统计大调 vs 小调比例，列出所有出现的 Key |
| 乐器 | 统计每种乐器的出现频率（如「钢琴 8/10 首，口琴 4/10 首」） |
| 歌词 | 合并所有意象词，按主题分类统计词频 |
| 制作 | 提取共性制作标签（如「10/10 首都有 warm tape saturation」） |

### Step 4：生成 DNA 指纹 + Style 配方词典（双输出）

将 Step 3 的综合结果转化为：

1. **7 维 DNA 指纹表**（每维度含分布数据 + 代表曲 + DNA 结论）
2. **BPM 分配建议**（按标杆的双峰/三峰比例分配到新专辑的 8 首歌）
3. **色彩乐器分配表**（每首一个差异化色彩乐器，来源于标杆的高频乐器）
4. **Style 配方词典（双输出）**：同一 DNA 要素、两种载体——① **标签式**（英文标签，可直接复制到支持标签的平台 Style 字段，≤平台字符上限）② **自然语言式**（中文单段 Style 指令：流派/BPM/声线/编曲/时长锚句）。两种载体按目标平台选择；配方参数以实测为准。

### Step 5：输出专辑参数

基于 DNA 指纹，生成可直接用于 `music-creation-workflow` 的专辑参数：

```
# 专辑参数输出格式
- 全专 BPM 分配表（8 首 × BPM）
- 每首调式建议
- 每首主导乐器 + 色彩乐器
- 每首歌词主题方向 + 意象词建议
- 全专人声统一特征
- 全专制作工艺标签
```

**输出路径**：项目调研目录 `dna-<type>.md`（作为专辑创作的 DNA 参考文件）

## 与其他 skill 的关系

```
music-trends-report（定类型方向）
        ↓
music-dna-extraction（提标杆 DNA）← 本 skill
        ↓
music-creation-workflow（按 DNA 创作专辑）
        ↓
voice-checker + lyric-reviewer + pre-generation-check（质量审查）
```

| 层级 | 负责 | 职责 |
|------|------|------|
| **上游** | `music-trends-report` | 识别当下流行类型 |
| **上游** | 自建历史标杆池报告 | 提供历史标杆歌曲池 |
| **本 skill** | `music-dna-extraction` | 从标杆提取可量化风格 DNA |
| **下游** | `music-creation-workflow` | 基于 DNA 参数创作每首曲目 |

## 常见错误

| 错误 | 修正 |
|------|------|
| 只调研 2-3 首就下结论 | 至少 8 首才有统计意义 |
| 取 BPM 平均值而非分布 | 平均值无意义——要看「60% 在哪个区间」 |
| 靠印象而非查数据 | BPM/调式必须多源交叉验证（吉他谱 + MIDI + SongBPM 等） |
| 在 Style 指令中引用标杆歌曲名/艺人名 | **硬规则**——标签式平台可能硬过滤（禁止）；自然语言式平台也保留零引用（工程卫生）。两种载体都只提取风格 DNA，不引用具体作品 |
| 把标杆的歌词意象直接搬用 | 提取的是「意象类型」（如「日常物件」），不是具体词汇 |
| 跳过 Step 3 跨歌综合 | 单首歌的数据不是 DNA——DNA = 跨歌的共性分布 |

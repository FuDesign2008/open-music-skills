# 短视频/流媒体音乐趋势调研报告（music-trends-report）

> **目标**：以「精准、可验证、可复用」的方式，产出面向短视频/流媒体核心受众的音乐趋势报告，服务新专辑选型与 Style 配方设计。
> **核心原则**：证据驱动、数据源透明、权重明确、局限坦诚。

## 前置检查（硬门控）

- 联网调研必须通过项目可用的 **web access 工具**执行（如 `web-access` skill；按该工具的安装与授权前置执行）。
- **工具缺失或采集失败即终止**——提示安装/授权后重试；不降级为裸 fetch、不编造、不臆填榜单数据。
- 派 subagent 采集时，prompt 写明工具的绝对路径或可用方式，避免 subagent 误判。

---

## 报告时效与选型校验（硬规则）

- 用于**新专辑选型**的报告：创作启动时距报告日期 **≤7 天**。超期时二选一：
  1. 出新一期完整/差量报告（走完整流程）
  2. 时间紧时出「**选型校验专项**」差量报告：只采最新榜单 + 搜索交叉，对照既有选型给出三选结论——**维持 / 修订 / 推翻**，并回写专辑索引的选型依据节
- **已生成/已上架专辑的追认校验**同样走差量流程，不能以「已经生成了」为由跳过。
- 每份报告头部必须标注**数据窗口与调研日期**；时效基准时点 = **创作启动日**，不是报告写作日。

## 工作流（5 Phases）

### Phase 0：范围确认（必须先问清）

| 参数 | 默认值 | 备选 |
|------|--------|------|
| 数据窗口 | 近 2 周 | 近 1 月 / 近 1 季度 |
| 平台权重 | 短视频系优先 | 全平台平权 / 海外优先 |
| 输出路径 | `<research-dir>/trends/YYYY-MM-DD.md` | 自定义 |
| 是否覆盖已有 | 询问 | 默认拒绝覆盖，用 `v2`/`v3` 后缀 |

**强制确认**：用户未明确时先问 1 次，不要默认硬跑。

### Phase 1：数据采集（多源并行）

**核心原则**：数据源 URL 必须来自 `references/data-sources.md`（已验证）；不得自创 URL。新增源先验证再写入。

**采集顺序**（按权重）：

1. **核心数据**（短视频系直接）——并行采集
   - 目标平台热歌榜（App 内可见；web 端无公开数据时，用手动截图或关键词侧写）
   - 现象级病毒歌曲（多源搜索，月份参数化：按调研时点填当月/近月）
2. **重要代理**（受众侧写）——短视频受众画像重合的第三方榜单
3. **辅助参考**（跨平台验证）——Apple Music / QQ 音乐 / 网易云等公开榜单

**禁止行为**：
- 不得把代理平台称为核心平台的数据
- 不得仅凭 Apple Music 数据下短视频结论（受众不重合）
- 不得引用未在 `references/data-sources.md` 验证过的 URL
- 提取失败时按条目的兜底方式处理（curl + UA / 官方接口 / 浏览器 CDP），不得编造

### Phase 2：跨源去重 + 权重排序

| 权重因子 | 分值 |
|---------|------|
| 核心平台出现 | ×3 |
| 代理平台出现 | ×2 |
| 辅助平台出现 | ×1 |
| 病毒侧话题热度 > 量级阈值 | +2 加成 |
| 跨平台共识（≥3 平台） | +2 加成 |

**产出**：跨源 TOP 20，每首含曲目/艺人/七类标签/核心表现/跨平台验证。

**关键纠偏检查（必做）**：
- TOP 5 是否被某一头部艺人效应主导 → 若是，重排序
- K-Pop 是否被辅助平台高估（在短视频系通常缺席）→ 若高估，降权
- 男声民谣是否被低估（短视频系真实占比常高于 Apple 视角）→ 若是，补正

### Phase 3：七类分析 + BPM + 制作签名 + 主题

详见 `references/trend-analysis.md`：

1. **七大旋律类型**：治愈系赫兹 / 颅内复读机 / 多巴胺和弦 / 锐舞炸场调 / 岁月金唱片 / 新腔唱古韵 / 燃感最强音
2. **BPM 区间分析**：短视频 BGM 常见黄金区 75–95 BPM；双峰检测（75–95 抒情 vs 120–128 卡点）；100–115 BPM 常为真空机会窗
3. **5 个最重要制作签名**（按当前 TOP 20 共有 DNA）
4. **歌词主题密度**（远方思念 / 人生感悟 / 童年怀旧 / 爱情释怀 / 玩梗反讽 / 励志燃向）
5. **缺口识别**：哪些类型在核心平台严重缺位（通常是新腔唱古韵/男性治愈系）

### Phase 4：Style 配方（核心交付，双形态）

**平台适用**：配方按目标平台给双形态——**自然语言式**（中文单段 Style 指令：流派/BPM/声线/编配/时长锚句）与**标签式**（英文 Style Prompt，≤ 目标平台字符上限，示例 1000 字符）。

**配方结构**（针对 Top 3 主导类型，每套含 6 要素）：

1. Style 构件（乐器/BPM/调式/人声/结构/纹理）
2. Sample Style 指令（自然语言式中文单段；标签式英文，字符数合规）
3. 歌词主题建议（具体场景 + 实物锚点）
4. 目标受众 / 场景
5. BPM & 调式推荐
6. 避坑清单

详见 `references/style-prompt-patterns.md`（7 类对应模板）。

### Phase 5：战略洞察 + 报告落盘

**5 条战略洞察**（必须可执行，不能空话）：

1. 下张专辑优先类型 + 主题 + BPM 范围
2. 必含的辅助类型（燃感/梗歌）
3. 必须采用的制作技巧（前 3 秒 hook、双轨分发等）
4. 分发时机与平台矩阵
5. AI 原生机会与风险

**报告落盘**：
- 路径：`<research-dir>/trends/YYYY-MM-DD.md`（v2/v3 加后缀）
- 格式：按 `references/report-template.md`（blockquote 元数据、中文编号、表格优先、sources 在末尾）
- 研究索引同步：在研究目录的索引文件中登记新报告

**落盘后必做验证**：
- 标签式 Prompt 字符数合规（自然语言式不适用 1000 字符硬限）
- 报告必有章节齐全（数据源权重/TOP 20/风格光谱/BPM/主题/配方/洞察/局限/来源）
- 代理平台归属标注正确（如代理平台属其他集团，不得写成核心平台数据）

## 与其他 skill 的协作

| 上游 | 本 skill | 下游 |
|------|---------|------|
| 无（数据采集自外部） | `music-trends-report` | `music-creation-workflow`（按配方创作） |
| | | `lyric-reviewer` / `voice-checker`（审查） |
| | | `pre-generation-check`（生成前关卡） |
| | | `audio-mastering`（平台允许替换音频时的母带） |

**推荐流水线**：

```
music-trends-report（定方向）
  → music-creation-workflow（按配方创作：写词 + Style）
  → voice-checker + lyric-reviewer（质量审查）
  → pre-generation-check（生成前关卡）
  → 生成
  → 发行与数据复盘
```

## 常见错误与红线

### 数据源错误

- 凭印象编 URL（必须用 `references/data-sources.md` 验证过的）
- 把代理平台当核心平台数据
- 直接用 Apple Music 数据下短视频结论
- 未经 web access 工具直接裸跑采集，或工具缺失时不报错仍硬跑
- 提取失败就放弃或臆填数据

### 范围漂移

- 用户要「近 2 周」，却跑成「近 1 月」（Phase 0 必须确认）
- 没问平台权重就硬跑（默认短视频系优先，但应明确告知）

### 结论空泛

- 战略洞察写成「建议关注治愈系」（应写「下张专辑做 6-8 首 78-88 BPM 男声民谣，主题远方思念」）
- 标签式 Prompt 超平台上限（必须脚本验证；自然语言式不适用）

### 格式不符

- 报告加 YAML front-matter（本项目文档规范禁止）
- 中文文档用英文标点
- 不更新研究索引

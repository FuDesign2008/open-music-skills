# 生成前关卡检查（pre-generation-check）

> **定位**：生成前的最后一道门。只报告 pass/fail，不修改文件。
> **平台适配**：长度、原创性声明、词量等平台专属项以**目标平台配置**为准；本 skill 给通用检查清单。

## 触发词

- **准备生成 / 生成前检查 / 可以生成了吗**：运行全部关卡
- **pre-gen check / ready to generate**：英文触发

## 适用范围

- 单曲目检查：项目中的单曲文件
- 整张专辑检查：专辑目录下所有曲目文件

---

## 11 道关卡

### Gate 1：Style Prompt 完整（平台分叉）

| 项目 | 检查内容 |
|------|---------|
| 检查 | Style 字段非空，非模板占位符 |
| 检查（自然语言式平台） | Style 指令完整：含流派/风格、BPM、声线、时长锚句 |
| 检查（自然语言式平台） | 词量达到平台时长模型的可靠区间（示例：慢/中板 3 分钟+ 约 580+ 字；快板/短行词例外） |
| 检查（标签式平台） | Prompt 字符数 ≤ 目标平台上限（示例 1000） |
| 检查（标签式平台） | 含原创性声明（`original composition` / `original song`） |
| 检查（标签式平台） | 含时长声明（示例 `Extended full-length piece approximately 4 minutes`） |
| 检查 | 含人声描述（歌词模式）/ 含 `instrumental` 标记（纯音乐模式） |
| 检查 | 含 BPM 和调式（如 `around 72 BPM in E minor`） |
| 严重度 | **BLOCKING** — Style 不完整无法生成 |

### Gate 2：歌词就绪

| 项目 | 检查内容 |
|------|---------|
| 检查 | 歌词段落非空，非模板占位符 |
| 检查 | 无 `[TODO]`、`[PLACEHOLDER]`、`TBD` 等占位标记 |
| 检查 | 含段落结构标记（`[Verse]` `[Chorus]` 等） |
| 检查 | 歌词裸文本中无制作指令：乐器提示、舞台说明、编配标注等不属于演唱内容的中英文指令 |
| 严重度 | **BLOCKING**（仅歌词演唱模式）— 裸文本会被当成歌词演唱 |

### Gate 3：艺人名已清

| 项目 | 检查内容 |
|------|---------|
| 检查 | Style/Prompt 中不含已知艺人/乐队名 |
| 参考 | 自建「艺人/乐队名清单」；平台过滤规则以目标平台为准 |
| 严重度 | **BLOCKING**（有艺人名过滤的平台）；无过滤器平台降为 **WARNING**（Style 零引用是工程卫生习惯） |

### Gate 4：显式标记已设

| 项目 | 检查内容 |
|------|---------|
| 检查 | 曲目文件中有 `Explicit: Yes` 或 `Explicit: No` 标记 |
| 检查 | 标记与歌词实际内容匹配（调用 `explicit-checker`） |
| 严重度 | **WARNING** — 可继续生成但发布前必须修正 |

### Gate 5：自检通过 + 结构层四查

| 项目 | 检查内容 |
|------|---------|
| 检查 | 曲目文件中的自检清单全部标记为通过 |
| 检查 | 情绪定调 / 声线描述 / BPM+调式 / 结构标记 / 歌词格式 |
| 检查 | 结构层四查已过：刻度匹配 / 降格红线 / 表里双层 / 升华度（详见 `lyric-reviewer` 第 9 点） |
| 严重度 | **BLOCKING** — 自检未通过或结构层四查未执行不可生成；升华度发现项为 Warning，交创作者判 |

### Gate 6：元数据唯一性（Info 软建议）

| 项目 | 检查内容 |
|------|---------|
| 检查 | 曲名不与专辑索引中已有曲目重复 |
| 检查（Info） | 曲名建议避免与已知热门歌曲同名，交创作者自判 |
| 检查（Info） | 艺名/专辑名建议避免与已有作品重复，交创作者自判 |
| 严重度 | **INFO** — 不阻断；同专辑内重名建议修正 |

### Gate 7：情绪光谱检查（多曲目时）

| 项目 | 检查内容 |
|------|---------|
| 触发条件 | 专辑含 ≥3 首曲目 |
| 检查 | 统计情绪分布，同一情绪是否 >50% |
| 严重度 | **WARNING** — 可继续生成但建议优化 |

### Gate 8：歌词可及性（中文歌词）

| 项目 | 检查内容 |
|------|---------|
| 检查 | 歌词中是否包含 2-3 个具体感官碎片或事件锚点 |
| 检查 | 陌生听众仅凭歌词能否理解「这首歌在唱什么情绪」以及「为什么」 |
| 检查（软指南） | 画面感自检：调用 `imagery-craft` 10 维度评分，标薄弱给建议 |
| 严重度 | **WARNING** — 可继续生成但听感可能空洞 |

### Gate 9：曲式光谱检查（多曲目时）

| 项目 | 检查内容 |
|------|---------|
| 触发条件 | 专辑含 ≥3 首曲目 |
| 检查 | 模式 B：统计各曲曲式骨架，同一段落模板是否 >50% |
| 检查 | 模式 A：审查动态曲线雷同 / 时长齐平；须脚本提取 `[Verse]/[Chorus]` 段落序列做名实校验 |
| 严重度 | **WARNING** — 可继续生成；BGM/冥想类专辑可豁免 |

### Gate 10：留白与起伏检查

| 项目 | 检查内容 |
|------|---------|
| 检查 | 单首：是否满密无起伏、副歌前有无战略性留白、词曲是否脱节 |
| 检查 | 留白实现方式是否可靠：静默首选下划线占位 + Style 自然语言；用 `[Silence]`/秒数指令标记为高风险 |
| 检查 | 多曲目：密处取气 vs 虚处取气是否双峰交替，避免全密/全疏单调 |
| 参考 | `whitespace-craft` |
| 严重度 | **INFO** — 软指南，不阻断；BGM/冥想类豁免 |
| 生成后提醒 | 含静默指令的曲目，生成后跑 RMS 深度低谷验证（`audio-mastering` 的 rms_silence_check） |

### Gate 11：原句占比测量（仅公版/改编项目）

| 项目 | 检查内容 |
|------|---------|
| 触发条件 | 项目涉及公版/改编/引用（非此类项目 SKIP） |
| 检查 | 用脚本测量原句直还占比（按唱次），输出「直还 % + 拆散骨架 %」双口径数字并写入曲目自检 |
| 检查 | 结构层三项：①曲名=原诗句/高搜索词 ②原词各句全还原或拆散入词 ③副歌原句主体 |
| 严重度 | **BLOCKING**（测量与结构层硬阻断）；口径分歧随批次上报创作者 |

## 宋韵提示项（Warning 非阻断，可选）

适用宋韵线/简素平淡方向的曲目；不改变 11 道关卡判定：

| # | 三问速查 |
|---|---------|
| T1 密度 | 意象域几个（≤2 族为绿）？音色族几个（≤3 为绿）？删一半还成立吗？ |
| T2 枯淡 | 抽掉高潮段还有听头吗？底下有没有暗劲（悬着的意象/未解的细节）？ |
| T3 韵 | 听完十分钟，还剩什么没被说破？用一句非歌词的话转述，是否正好说尽？ |

详见 `songyun-craft` 八测试。

## 器乐纯音乐处理

当曲目文件标明 `instrumental: true` 或 Prompt 中含 `instrumental`：

- **跳过** Gate 2（歌词就绪）、Gate 4（显式标记）、Gate 8（歌词可及性）
- Gate 1 调整：不要求人声描述，改为要求流派/乐器/情绪描述
- Gate 3/5/6/7/9/10 正常执行（Gate 9/10 对器乐尤其重要）

---

## 工作流

### 单曲目

1. Read 目标曲目文件
2. 判断是否为器乐纯音乐
3. 逐关检查（跳过器乐不适用关卡）
4. 输出 pass/fail 报告

### 整张专辑

1. 收集专辑目录下全部曲目文件
2. 逐首检查
3. 汇总专辑级别判定

## 检查原则

1. **你是门，不是修理工**：只报告问题，不修改文件。
2. **BLOCKING = BLOCKING**：阻塞关卡不通过绝不说「可以谨慎生成」。
3. **具体到行**：报告问题必须精确到文件 + 位置，不能只说「某关没过」。
4. **器乐曲目跳过歌词关**：Gate 2/4/8 对器乐曲目不适用。
5. **艺人名很狡猾**：仔细检查 Prompt 全文，对照自建清单。

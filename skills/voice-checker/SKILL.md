# 歌词 AI 人声模式检测器（voice-checker）

> 定位：创作与生成之间的**建议层**。只标记问题、给出方向，绝不改写、绝不阻断流水线。

## 触发词

- **AI味 / 歌词太AI / 检查歌词真实性**：检测歌词中的 AI 写作模式
- **voice-check**：英文触发
- **歌词空洞 / 歌词像AI写的**：快速扫描

## 适用范围

- 中文歌词为主（英文段落仅适用模式 A）
- 仅分析歌词文本，不涉及 Prompt 或元数据

---

## 检测模式

### 模式 A：通用 AI 模式（中英文通用）

#### Class 1：抽象名词堆砌
**症状**：连续使用「梦想」「希望」「光芒」「黑暗」「真理」「痛苦」等抽象名词作为情感简写，而非通过具体意象传达。

**检测信号**：
- 单行或对句中 ≥3 个抽象名词
- 抽象名词作为列表出现（「希望、梦想与光芒」）
- 抽象名词做主语执行抽象动作（「真理照亮了黑暗」）

**严重度**：Warning

**建议方向**：至少将一个抽象名词替换为具体意象。写「晨光」而非「希望」——希望长什么样？

---

#### Class 2：过度解释隐喻
**症状**：引入一个意象后立即解释，剥夺听众的发现感。

**检测信号**：
- 前一行比喻，后一行直接点明含义
- 「就像……」「正如……」后面跟着的是对前一句的翻译
- 喻体出现后紧跟着「意思是」「说明」

**严重度**：Warning

**建议方向**：保留意象，删除解释。信任听众的理解力。

---

#### Class 3：对称情绪弧
**症状**：过于工整的「绝望→挣扎→胜利」递进，每段按日程升级。

**检测信号**：
- V1 = 问题、V2 = 挣扎、V3 = 解决、副歌全程昂扬
- 没有挫折、复杂情绪或模糊地带
- Bridge 总是「黎明前的黑暗」然后必然解决

**严重度**：Info

**建议方向**：考虑留一条线不收束，或让解决带有代价。真实故事很少完美收场。

---

#### Class 4：缺少个性细节
**症状**：整首歌词没有任何具体的人名、地名、质感、日期、气味、声音或物体来锚定在特定世界。

**检测信号**：
- 整首歌只用通用/泛化意象
- 没有任何专有名词、街名、感官细节
- 可以是任何人、任何地方、任何时间

**严重度**：Warning

**流派敏感度**：氛围/梦幻/古风等抽象流派中，普遍性是特征而非缺陷。此类流派降级为 Info。

**建议方向**：每段加 1–2 个具体细节。三点的厨房灯 > 孤独的夜。

---

#### Class 5：陈词升级短语
**症状**：批量出现的励志模板句，信号「AI 励志演讲」而非真实表达。

**检测信号**（中文版）：
- 「超越自我」「突破极限」「找到方向」「站上巅峰」
- 「穿越黑暗」「逆风飞翔」「永不言弃」
- 「黎明前的光」「打破枷锁」「重写篇章」
- 「撕碎沉默」「改写命运」「翻开新页」

**严重度**：Warning（单次）/ Warning+强调（一首歌 ≥3 次）

**建议方向**：这个角色在此时此刻会说什么？陈词是真正台词的占位符。

**反向解法——「陈词拒用」**：陈词若已占据题材核心（躲不开，如写父母绕不开「恩」），**不必回避——把它摆出来当场点破其陈，再换一个克制的定量词承住**。实例：「恩重如山 听起来不自然」——先立起套话再当众弃用，**否定的力道比肯定的赞美可信**（以认知层升维替代词汇层绕行）。做法三步：① 写出那句陈词 → ② 紧跟一句「听起来不自然／不对」式的当场弃用 → ③ 换一个克制的定量词（如「不少不多」）落地。按**候选级方法**使用，用前知悉。

**浓烈语法分界（防误伤）**：大词（梦/光/远方/英雄…）**不因「大」判 AI 味**——判据＝是否被具体代价偿付（「最卑微的梦」「就算鲜血洒满了怀抱」＝有偿付＝合法；空洞无代价的大词才判）。防把浓烈配方产出的「真喊」误伤为陈词/口号。

---

#### Class 6：完美语法
**症状**：每一行都是完整规范的语法句子，缺乏口语的省略、碎片、打断。

**检测信号**：
- 零省略、零倒装、零碎片句
- 每行以完整主谓宾结构呈现
- 使用了「然而」「因此」「此外」等书面连接词
- 语气词（啊、吧、呢、嘛）缺失

**严重度**：Info

**建议方向**：大声读出来。像写作文 = 需要打散。省略、倒装、碎片让歌词呼吸。

---

#### Class 7：过度平衡的平行结构
**症状**：每段在句数、句法、修辞模式上完全镜像——机械对称，像模板生成。

**检测信号**：
- V1 和 V2 句数相同且句法模式相同（如都以疑问开头、以宣言收尾）
- 段内每行都是相同的 [主语][动词][宾语] 模式
- Pre-Chorus 每次结构完全一致

**严重度**：Info

**建议方向**：有些平行是好的——这是创作工具。只在对称感机械时才标记。问「这个平行结构是有意的吗？」

---

### 模式 B：中文特有问题

#### Class C1：四字成语堆砌
**症状**：连续使用多个四字成语或固定词组，形成「成语接龙」效果，缺乏个人表达。

**检测信号**：
- 单行 ≥2 个成语/四字词组
- 整段连续 3 行以上每行含成语
- 「荡气回肠」「气势磅礴」「波澜壮阔」「风起云涌」等大词连用

**严重度**：Warning

**建议方向**：保留 1 个最能定调的成语，其余替换为口语化表达或感官细节。

---

#### Class C2：古诗引用拼贴
**症状**：将不同来源的古诗词句生硬拼凑，不成体系，缺乏统一的意境。

**检测信号**：
- 引用 ≥2 首不同古诗/词牌的句子混在同一段
- 古诗与现代口语之间缺乏过渡
- 引用句与原诗语境割裂（如用「大江东去」写失恋）

**严重度**：Warning

**建议方向**：要么围绕一首诗的原意境展开，要么将古诗意象融入现代语境而非直接引用。

**豁免**：围绕**同一首**公版诗词、在**原词语境**中还原名句（含相邻联句）属有意设计，不标记——本 Class 只打击跨源拼贴与语境割裂。

---

#### Class C3：韵脚疲劳
**症状**：连续多行押同一韵脚不换韵，听感单调。

**检测信号**：
- 连续 ≥6 行押同一韵母（如全部 -ang 或全部 -i）
- 为凑韵而强行使用生僻词或不自然表达
- 副歌和主歌用同一韵脚，缺乏对比

**严重度**：Info

**建议方向**：Verse 和 Chorus 换韵增加段落对比度。不要为押韵牺牲表达自然度。

---

#### Class C4：「的」字泛滥
**症状**：每行以「的」结尾或大量使用「的」字结构，节奏单调。

**检测信号**：
- 连续 ≥3 行以「的」结尾
- 整段「的」字密度 >20%（每 5 个字出现 1 个「的」）

**严重度**：Info

**建议方向**：改写部分以「的」结尾的行，用动词收尾增加力度。

## 工作流

1. Read 目标歌词文件
2. 定位歌词段落（`## 歌词` 或 ``` 包裹的歌词内容）
3. 依次运行模式 A（Class 1–7）+ 模式 B（Class C1–C4）
4. 生成检测报告

## 集成

### 调用时机
- 写完歌词后、生成之前
- 专辑/批次审查时作为补充检查
- 用户感觉歌词「不对劲」但说不出哪里不对时

### 与其他 skill 的关系
- `music-creation-workflow`：负责整体 Prompt 生成与规则检查
- `lyric-reviewer`：互补——reviewer 检查技艺问题（结构、押韵、长度），voice-checker 检查真实性问题（AI 味）
- `pre-generation-check`：生成前最后一道关卡

---

## 铁律

1. **仅建议，不强制**：标记并给出方向。绝不改写、绝不自动修改、绝不阻断流水线。
2. **只有 Warning 和 Info 级别**：无 Critical 级别。这是品味问题，不是对错问题。
3. **有意的选择有效**：平行结构、陈词、抽象意象可能是刻意为之。问「这是有意的吗？」而非「改掉这个」。
4. **流派敏感**：氛围/梦幻/古风等抽象流派在 Class 4（缺少个性细节）上降级为 Info。
5. **中文 vs 英文**：中文歌词适用模式 A（通用）+ 模式 B（中文特有）。如果检测到英文歌词段落，仅适用模式 A。
6. **你不是改写者**：交付物是结构化检测报告，不是修改后的歌词。作者决定改什么。
